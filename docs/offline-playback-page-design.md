# 离线播放页设计

2026-11-22 · 离线播放页设计与实现。用户从下载中心打开一集后，可以读到这部作品的本地简介，并在同一播放页切到另一集、分 P 或作品。

## 页面布局

沿用普通视频和影视页的播放器、侧栏开关、字号、间距与下划线标签。封面用于「全部下载」的作品行。播放页首屏把这块空间留给画面，省去现有的播放器上方大封面。返回下载放在顶部导航，与播放器内的全屏返回分开。

| 区域 | 宽屏 | 窄屏 |
| --- | --- | --- |
| 画面 | 左侧占满剩余宽度。沿用现有分栏阈值，默认 1000 逻辑像素，右栏宽 380。侧栏收起后画面扩展 | 画面置顶。横向视频以 16∶9 起步，竖屏素材和听视频沿用共享布局。浏览长列表时保留播放器 |
| 作品信息 | 默认在右栏顶部。按内容类型继承普通视频或影视页已有的「右侧／下方／自动」偏好。摘要移到画面下方时，选集和全部下载仍留在右栏 | 画面下依次是作品名、当前 P／集标题、一行本地信息、可展开简介。上下滚动时摘要先移出，列表继续使用剩余空间 |
| 列表 | 作品信息和列表用分隔与留白区分。当前作品的列表默认可见，「全部下载」在同一标签行 | 与宽屏共用相同标签和内容。当前项用主题强调色、播放图标和文字标识。长标题最多两行，大字号时辅助信息可换行 |

普通视频显示投稿标题、UP 主和投稿简介。番剧、国创与影视显示季名、当前集名和**整季／作品简介**，不把季名再显示成 UP 主。标题与分 P 名相同时只显示一次。摘要行保留「本地 · 1080P · 24:10」这类与观看直接相关的信息。编码和封装格式放进本地版本信息。简介默认两行，超长可展开，缺失时收去该行。收起简介和收起整个信息区各自独立。

以纪录片《湖岸四时》为例，宽屏默认状态如下。示例作品和集名为虚构，交互预览中的示意帧来自本机 Windows 随附的风景壁纸。

```text
返回下载
┌──────────────────────────┬────────────────────────┐
│                          │ 湖岸四时 · 第一季       │
│                          │ 第 3 集 · 山林的倒影    │
│         本地视频          │ 本地 · 1080P · 23:48   │
│                          │ 作品简介……  展开       │
│                          ├────────────────────────┤
│                          │ 本季剧集  │  全部下载   │
│                          │ 正片                   │
│                          │   01  水边的清晨        │
│                          │ ▶ 03  山林的倒影        │
│                          │   08  静水入冬          │
│   播放进度与共享控件       │ 花絮                   │
└──────────────────────────┴────────────────────────┘
```

## 两个列表分别怎么用

- **当前作品**的标签按内容显示为「本季剧集」「视频分 P」或「视频合集」。打开时定位正在播的那一项，按作品原顺序列出已下载内容。例如只下载了第 1、3、8 集，就显示第 1、3、8 集及「已下载 3 集」。没有可靠总数时只显示本地数量。无合集的单条下载直接显示「全部下载」，省去只有自己的一行；已知属于多集、分 P 或合集的作品即使只下载了一项也保留上下文。
- **全部下载**展示当前账号已完成的内容，按作品分组，以组内最近任务的创建时间倒序。每组只占一行，显示本地小封面、作品名和已下载数量。展开可查看具体集／P，点击具体条目才切换播放。封面缺失使用本地图标。下载队列、重试和删除保留在下载中心。
- 同一集／P 的不同画质、编码或封装合并为一行，显示「2 个版本」等入口。由下载中心打开时尊重所点任务。列表内切集优先沿用上一项的画质、编码和格式，多项同等匹配时选较新的任务。用户可从版本入口改选实际文件；集数与播放队列均按内容去重。
- 上一项、下一项和播完行为以当前作品内的本地顺序为准。PGC 有分区资料时以正在播的正片或花絮分区为界。连续播放走到末尾停止，列表循环只在该范围循环，单集循环与播完暂停沿用既有设置。「全部下载」用于选片，浏览或展开其他作品不会改变播放队列。切换到另一作品的具体条目后才更新队列。

## 改版前的下载保存了什么

下表是改版前的 v1／v2 任务基线，封面、字幕和弹幕取决于实际下载结果。新版本额外保存的内容见下一节。

| 内容 | 当前重启后可读 | 对本页的影响 |
| --- | --- | --- |
| 普通投稿 | BV 号、可选 AV 号、投稿标题、作者名、时长。每个下载项有 CID、原始 P 序号、P 标题和时长 | 可按同一 BV 组装已下载分 P。没有投稿简介、总 P 数和跨 BV 的合集归属 |
| 番剧／影视 | 季 ID、集 ID、季名、合成的集标题、原列表位置和时长。作者字段实际填季名 | 可按季组装旧下载并保留相对顺序。没有整季简介、正片／花絮分区、完整季目录。列表位置不能当作官方集号 |
| 本地版本 | 画质、所选编码、实际轨道记录、分轨／MP4／MKV、任务状态、创建时间、文件索引和附属警告 | 足够列出当前账号的已完成项、显示本地版本及打开具体文件 |
| 附属内容 | 可选的本地封面、字幕和弹幕。完成清单记录媒体及轨道，附属 JSON 记录字幕、弹幕和警告 | 均不能提供作品简介或合集目录。「包含字幕」开关也不能代替实际字幕文件内容 |

两个下载入口已经收到完整的 `VideoDetail` 或 `PgcSeason`。前者提供投稿简介、分 P 和可选合集，后者提供作品简介、集标题及分区。当前普通视频下载候选取自**当前 BV 的分 P**；播放页展示已分别下载的同合集投稿，不要求把下载弹窗扩展成整合集批量下载。当前合集解码保留跨视频顺序，已将原始章节展平成投稿列表，首版按「合集 → 投稿 → 分 P」展示。

依据见[下载项构造](../lib/features/downloads/domain/download_models.dart)、[任务持久化](../lib/features/downloads/data/sqlite_download_repository.dart)、[完成清单与附属文件](../lib/features/downloads/data/download_file_store.dart)、[在线投稿模型](../lib/domain/video.dart)、[影视模型](../lib/features/pgc/domain/pgc_repository.dart)及[合集解码](../packages/bili_api/lib/src/api_client.dart)。

## 新下载的分组与持久化

| 内容 | 分组和排序 | 入队时保存的补充信息 |
| --- | --- | --- |
| 单投稿／多 P | 账号 + BV 号；组内以 CID 辨认每一 P，按原始 page 排序 | 按 BV 保存投稿简介和已知总 P 数 |
| 跨投稿合集 | 账号 + UGC 合集 ID；按合集原始投稿位置，再按该投稿的 P 序号。多 P 投稿展开，单 P 投稿直接可点 | 合集 ID、合集名及当前 BV 在合集中的位置。有可靠归属时将投稿列入合集，保留其 BV 及分 P 身份 |
| 番剧／影视 | 账号 + PGC 季 ID；按集 ID 区分集、按来源顺序排列。正片与预告、花絮等使用来源分区。不同季分别展示 | 按季保存作品简介；每个已下载集保存来源分区、显示集号／短标题、长标题和原始位置。PGC 与 UGC 的数字 ID 使用独立类型 |

新任务的 JSON 版本为 3，保留旧版字段，增加可选的剧集分区、短标题和长标题。作品简介、季类型、总 P 数和合集归属在 SQLite 中按账号和作品身份各存一份，使用既有键值表的 `downloads.work.v1/` 命名空间。新任务和作品资料在同一事务提交；删除最后一个关联任务时同时清理资料。数据库表结构沿用版本 3。

旧任务继续按原结构解码。相同账号、相同季或 BV 已有新快照时可共用简介、分类和合集归属。缺少合集关系就按 BV 展示。影视分区全都缺失时平铺原集名；新旧记录混合时，无法确认分区的集放在「未分区」。进入页面、浏览和选集时只读取本地索引和选中任务的文件。

## 下载中心的已完成分类

「已完成」下提供「全部、视频、番剧、国创、影视」。普通投稿和 UGC 合集成员归入「视频」。影视季详情的类型 1 对应番剧，4 对应国创；电影、电视剧、纪录片、综艺和缺少可靠类型的旧影视下载归入「影视」。分类与标题／分集搜索叠加，下载中心仍按实际文件版本列出任务，保留播放、打开目录和删除操作。播放页内的作品列表按内容去重，版本可在行内选择。

## 播放交互与验收

1. 从下载中心点开的任务就是首播版本。切集更新当前工作区播放标签的本地目标；同一标签只拥有一个播放会话。切标签、收放侧栏、展开简介和浏览其他作品均保留当前播放进度。全屏、听视频和返回沿用普通播放页的行为。
2. 列表从当前账号的完成索引建立，不逐项打开媒体。选择目标时走现有本地文件／公共存储访问检查。目标文件已移走时显示具体失败原因，保留列表和可选的其他版本；缺封面、弹幕或字幕仅作附属提示。删除任务、账号切换或连续快速选集时，旧结果不得覆盖新目标。
3. 验收以断网、重启后能打开为准。覆盖单条视频、只下载 P2/P5、跨 BV 合集中一个投稿又含多 P、同名不同季、正片与花絮、同一集多版本，以及无简介／无合集快照的旧任务。检查数量、原始顺序和播完边界，并确认打开和切换时没有在线详情、推荐、评论或云进度请求。
4. 用宽屏、390／320 窄屏、大字号、深色主题和侧栏开关检查标题与列表可读性；在窗口缩放、全屏切换和快速换集时检查选中项、列表位置与音频会话。
