## 改动方案

- 热门的综合热门、每周必看、入站必刷、排行榜改为截图所示的内容子标签：左对齐、13px 字号、玫红选中文字、浅灰圆角悬停背景，不带图标和下划线。提取首页现有番剧等内容子标签的共享组件，保持横向滚轮、窄屏滚动、分页切换与选中语义；首页一级频道、直播和消息的标签层级不变。
- 动态页恢复头像和搜索，根页面仍不显示历史、下载、设置工具。按后续用户要求，首次从一级导航进入时默认“动态”子标签；本次运行期间记住用户手动选过的动态分类，显式旧频道链接继续生效。
- 动态导航改为易辨识的动态订阅图标，未选中时仍保留完整图形；桌面侧栏、移动底栏和根工作区标签共用映射。
- 双标签桌面播放窗口在当前应用运行期间记住用户调整的正常窗口大小和位置，关闭并重新打开视频、影视、直播或离线播放仍恢复。首次沿用默认尺寸，不写设置或数据库；退出应用清除。保存与恢复限定到播放窗口，防止最大化、最小化、全屏及过期关闭事件覆盖正常边界，并处理显示器变化和不可见位置。

沿用已授权的 Sol 6.1 xhigh 子代理，分别负责内容子标签、动态外壳、窗口适配；主代理审查集成、生命周期、文档和验证。保留当前未提交修改，不更新依赖、SDK 或 Pub 缓存。

自动回归覆盖动态初始分类与后续选择、头像搜索与入口图标、热门切换和窄屏；窗口使用 fake/native channel 边界测试验证会话记忆与关闭竞态。最终运行 `tool/check.ps1 -SkipPub` 并仅构建 Windows Release。按用户要求不启动或操作客户端，不执行实机、原生集成和性能测试，不构建 Android/macOS；实际拖动、关闭重开、跨显示器和全屏体验由用户手动验收。

## 追加：会话内保留最大化状态

用户要求关闭最大化播放窗后，再打开任意媒体仍保持最大化。正常窗口矩形与最大化标志分开存储，先恢复普通矩形再最大化，点击还原时仍回到用户此前的位置和尺寸；用户主动还原后，后续重开也应为普通窗口。最小化和全屏不替代这两项状态，应用退出清空，保留 view/owner 隔离与首帧前恢复顺序。

固定 Flutter SDK 的窗口控制器同步监听当前最大化状态，以保留最小化前的状态；跨窗口记忆仍只由原生通道持有。Windows 用正常屏幕矩形和原生最大化，macOS 用正常 frame 和 Cocoa zoom；不恢复全屏、不写设置或系统窗口 autosave。补充几何状态和通道回归，执行根检查，再只构建 Windows，用户手动验收。

后续实机反馈发现 Windows 首帧的 SDK 普通显示会覆盖提前恢复的最大化；当前已调整为首次原生显示后应用最大化，定位和回归见[第七轮调整](seventh-round-plan.md)。
