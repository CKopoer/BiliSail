# UP 主与个人主页自适应重构

日期：2026-11-05。

## 参考与范围

只读参考相邻 PiliPlus `265f879fa85973b4bf885bde2562f1007f1013b8` 的 `lib/pages/member/view.dart`、`member/widget/user_info_card.dart`、`member_home/view.dart`、`member_video_web/season_series/controller.dart`、`member_season_series/controller.dart` 和 `http/member.dart`。其应用为 GPLv3，本轮仅借鉴信息层级、交互职责和 Web 协议字段，独立实现布局、状态和模型；不复制其源码、图片、字体、schema 或引入相邻运行时依赖。

现有主页已具备投稿搜索/排序/播放全部、动态、收藏夹及队列、关注/粉丝、关注分组、私信和直播入口。本轮补齐空间头图、原图预览、资料详情、复制 UID/主页链接、官网入口、合集/系列和追番/追剧浏览。自己的公开主页与 UP 主主页共用实现，账号页继续负责历史、稍后再看、收藏和下载等私有内容。官网入口承接资料编辑等站点能力，不增加没有业务实现的按钮。商城、充电/舰长、预约和 App token 专属内容不属于本轮核心观看主页范围。

## 布局方案

- 按内容区约束判定宽窄，不按操作系统或设备类型。小于 600 逻辑像素采用头图、头像、统计、身份、简介和操作的纵向层次，资料与列表同距离滚动，内容导航吸顶。
- 宽屏头图高度受限，身份资料与统计/操作横向分区；超长名称、认证、字体放大允许换行，空间不足时回到纵向排列。宽屏资料保留有界独立滚动，避免吞掉列表视口。
- 简介默认显示有限行，展开保留完整文字和选择复制；详情在当前工作区内展示。头像与头图复用原图查看器，远端图片复用有界图片缓存和隐藏页请求限制。
- 保留投稿的横向视频卡，宽屏多列；收藏夹/合集以封面卡片展示，追番/追剧使用海报卡片；动态最大阅读宽度沿用 780。所有未知长度列表惰性构建。
- 导航保留投稿、动态、收藏夹，补充合集、追番、追剧，关注/粉丝仍可从统计和标签抵达。保留横向分页、已访问页面、滚动、搜索草稿与排序。

## 数据与状态

协议只进入 `bili_api`，领域模型与 Repository 由 profile 功能拥有，控制器负责请求、分页和错误，页面只渲染领域数据。头图等扩展资料独立读取，失败不能阻塞已成功的基本资料和投稿；显示可重试入口，不将失败当作空成功。合集与收藏夹使用独立身份、路径和请求代次，不能互相污染。追番/追剧分别分页并使用既有影视路由。

所有读取沿用 ApiRequests 的账号 scope/session epoch、取消与总 deadline，协议层有界重试；列表上限 500，重复页面保护沿用现行规则。页面切换不引发账号写操作，关注/私信沿用共享组件。

## 验收

以 fake transport/repository 验证新协议结构、ID 精度、分页与错误；以组件测试覆盖宽窄布局、字体放大、资料展开与菜单、合集/收藏切换、追番追剧跳转、请求取消和账号切换。运行主页回归及 `tool/check.ps1 -SkipPub`，检查文档链接与差异，只提交本任务文件。运行构建、在线烟测和设备验收结果另记，不从组件测试推导真实账号或三端验收通过。
