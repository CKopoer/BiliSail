# 对照 PiliPlus 简化两后端跳转与准备流程

日期：2026-11-08（Asia/Shanghai）。本轮继续处理跳转时反复出现“正在准备音视频／加载中”的问题，补充并调整[上一轮控制简化](player-control-simplification-2026-11-08.md)。用户后续允许构建和原生测试，本轮不沿用上一轮“未构建”的结论。

## 参考与原因

只读参考 PiliPlus `265f879fa85973b4bf885bde2562f1007f1013b8` 的 `lib/plugin/pl_player/controller.dart`、`lib/plugin/pl_player/view/view.dart` 和 `lib/utils/storage_pref.dart`。其位置／缓存／buffering 来自原生事件；seek 直接下发播放器，普通 play 直接继续；初次加载与播放中的实际 buffering 分开显示。参考工程的媒体核心／库插件实际锁定 `73771ec38176be2d984a3049c28177bce23b54a0`，视频包为 `85f0a69ea66b100882b27a3375c72e5155375343`，本应用不跟换依赖。

仅借鉴职责与交互，独立编写代码，没有复制 GPLv3 应用源码／资源、引入全局控制器或修改相邻仓库、Pub 缓存。

本项目此前存在三处重复：

1. 界面将 `isSeeking` 无条件归入初次准备，缓存内跳转也会出现整组准备提示。
2. 后端已经确认目标，共享层仍先发布 paused，再运行一次暂停、音频确认、画面确认、增益／音量恢复和 play。正常暂停后继续也重走同一流程，并人为设置 buffering。
3. media_kit 取消任何在途目标都执行 stop／loadfile，连可以原生替换的目标也丢弃缓存。

## 现在的共同契约

- **首次打开与首次就绪**继续校验轨道、音频与输出。普通继续沿用已确认状态，只下发 play，不重置音频就绪、不强制暂停或重施增益／音量。
- **一次 seek 只有一个目标确认屏障。** `PlaybackBackend.seekTo` 返回时，所需原生音视频已到目标。media_kit 使用 native SEEK／PLAYBACK_RESTART；fvp 的 `FvpPlayerPort.seek` 已同时定位视频和真实音频伴随管线，进程内及 Android IPC 沿用同一完成语义。共享层只发布确认位置，再按最新播放／暂停意图继续；没有第二轮准备。
- **seek 与 buffering 独立。** seek 仍冻结确认时间线、弹幕和旧事件；它本身不写入网络 buffering，也不经过一个假的 paused 状态。只有原生 buffering 事件改变缓冲标记。
- **缓存沿用当前原生端点。** 目标确认后立即读取当前后端的缓存端点，避免先把缓冲条清到当前位置再等下一次采样。缓存由原生持有，不增加字节代理、时间索引或额外下载器。
- **原生证据不经显示裁剪。** 缓冲条仍不画到当前位置之前；健康检测直接消费原生缓冲端点，保留视频先耗尽而音频仍推进的证据。这个值只在既有采样中传给原有检测器，不增加探针、状态机或恢复预算。
- **提示跟随实际工作。** 初次解析／打开显示准备，真实恢复显示恢复；普通 seek 不显示准备。仅用户想播放且原生持续缓冲 300ms 时显示网络缓冲，短暂脉冲不闪提示，暂停和 EOF 不显示旧缓冲遮罩。提示不拦截画面交互，换源和销毁取消等待。

这些决定统一位于共享引擎与共享 UI，两个 SDK 适配器不各写一套产品状态。

## 必要的 SDK 差异

media_kit 普通 seek 直接交 mpv，保留原生播放意图和包缓存。取消旧 Dart 等待时优先原生替换目标；原生测试确认，旧 HTTP 响应被完全阻塞时单纯替换仍会等待旧读取，因此仅在原生 buffering 的在途操作被取消时保留 stop／原源目标重载，解除阻塞。它不会对外重新发布 opening，也不会再次运行共享首次准备。

fvp 仍需在暂停中定位 MDK 两条实际管线，保留其原生音频主时钟、SDK 回调槽退休、EOF 的有界重准备和 Android 进程隔离。这些是适配器的原生要求，不增加第二个会话、第二层准备或额外重试预算。

原生断网缓存用例进一步发现，fvp 原先全部使用普通精确 seek，已缓存的前向目标也会重新读取网络。现仅在当前管线有效、目标严格前向且位于原生剩余缓存内时使用 `FromStart | InCache`，视频与真实音频管线分别核对自己的范围；反向、缓存外和重准备仍使用普通精确定位。范围依据 [MDK SeekFlag 契约](https://github.com/wang-bin/mdk-sdk/wiki/Types#enum-seekflag-flags)，不使用关键帧快速跳转替代精确目标。

默认两分钟普通／五秒预览缓存窗口、有限故障恢复、账号与源代次、暂停意图、释放屏障及原生内存上限不变。没有用缓冲条代替双轨目标就绪，也没有按码率估算缓存。不同 SDK 的缓存能力仍需分别验证，不能仅凭相同提示宣称性能相同。
