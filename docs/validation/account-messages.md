日期：2026-10-06。环境：Windows x64，Flutter 3.47.6 / Dart 3.13.5。按用户要求参考相邻 UWP 客户端和 C# API 内核提前接入，不代表完整阶段或三端验收。

## 交互与范围

已登录时点击右上头像，打开从右侧滑入的全高账号面板。面板占屏幕宽度的 80%，上限 360 逻辑像素；内容避开系统安全区，关闭按钮固定在顶部，资料和入口可滚动。点击遮罩、关闭按钮、系统返回或 Esc 可关闭。显示头像、昵称、等级/经验、会员标签、硬币、关注/粉丝/动态数量；最高等级的 `next_exp="--"` 显示“已满级”，缺失资料显示占位并提供重试。未登录沿用登录窗口。

| 按钮/信息 | 当前行为 |
| --- | --- |
| 个人中心 | 打开自己的独立用户标签 |
| 关注、粉丝、动态统计 | 打开自己的用户页并选中对应列表 |
| 我的消息 | 打开可复用的消息标签，头像和菜单显示未读总数 |
| 历史记录、稍后再看、我的收藏 | 跳转“我的”页对应内容标签，复用已保留的列表与筛选状态 |
| 直播中心 | 跳转现有直播“我的关注”；未扩展 UWP 的装扮/签到能力 |
| 退出登录 | 复用现有凭据清理与账号任务取消 |

消息页包含私信、回复我的、@我的、收到的赞和系统通知。消息页属于独立页面，不显示顶部推荐、热门等首页频道；内部五类消息采用与搜索、设置分类一致的文字按钮、主题色和选中下划线，保留未读数量，支持横向拖动和桌面鼠标滚轮。宽窗口使用会话/正文双栏，窄窗口在列表与会话间切换；作者可打开用户页，支持的 BV 链接在应用内打开，其他允许的 B 站链接交由系统浏览器。

私信支持会话列表分页、加载更早消息、文本发送和独立的“标为已读”按钮。打开未读会话并成功显示正文后自动提交已读回执，具体条件见下方 2026-10-25 补充记录。发送限 1–1000 个 Unicode 字符，失败保留草稿；网络/超时导致结果不明时提示刷新核对，不自动重发。系统/群组会话关闭文本发送。图片消息可阅读；撤回内容不解析或展示，暂不支持的富消息显示类型提示。系统通知实测没有可用翻页游标，当前仅显示最近 20 条，并提供官方消息页入口。

## 端点登记

均使用 Web Cookie profile；以下读取不需要 WBI。所有 JSON 经协议包映射为不可变领域模型，页面不解析响应。

| host | method / path | 参数、响应与分页 |
| --- | --- | --- |
| `api.bilibili.com` | GET `/x/web-interface/nav`、`/x/web-interface/nav/stat` | 校验 `isLogin` 和当前 MID；读取 `level_info`、`vip_label`、`money`、`wallet.bcoin_balance` 与三类统计 |
| `api.bilibili.com` | GET `/x/msgfeed/unread` | `chat/reply/at/like/sys_msg`；缺失计数按 0 处理 |
| `api.vc.bilibili.com` | GET `/session_svr/v1/session_svr/get_sessions` | `session_type=1`、折叠和排序参数；`session_list/has_more`，`end_ts` 为十进制微秒游标 |
| `api.bilibili.com` | GET `/x/polymer/pc-electron/v1/user/cards` | `uids` 为逗号分隔十进制 ID；读取按 MID 键控的资料对象，兼容列表形态 |
| `api.vc.bilibili.com` | GET `/svr_sync/v1/svr_sync/fetch_session_msgs` | `talker_id/session_type/size=30`；`messages/has_more`，`end_seqno` 为十进制序号 |
| `api.bilibili.com` | GET `/x/msgfeed/reply`、`/at`、`/like` | `id` 与 `reply_time/at_time/like_time`；`cursor.is_end`，点赞合并 `latest/total` 并去重 |
| `message.bilibili.com` | GET `/x/sys-msg/query_user_notify` | `page_size=20/build=0/mobi_app=web`；`system_notify_list`，`time_at` 可为日期字符串；空 `data` 是有效空列表 |
| `api.vc.bilibili.com` | POST `/web_im/v1/web_im/send_msg` | 单人文本私信；原始 JSON 文本交传输层编码一次，携带 `csrf` 和 `csrf_token`；仅显式发送触发 |
| `api.vc.bilibili.com` | POST `/session_svr/v1/session_svr/update_ack` | `talker_id/session_type/ack_seqno`；确认已显示的最新序号，携带 CSRF；打开未读会话后自动触发，也保留显式按钮 |

VC 写入口只允许上述两个固定路径，Cookie 按目标 host/domain/path/secure/expiry 筛选，Origin/Referer 使用消息站点，保留系统 TLS 验证。GET 沿用共享协议层最多 3 次尝试、单次 12 秒超时及 Repository 总计 25 秒 deadline；消息 Feature 不叠加重试。POST 单次尝试，不自动重放。

## 状态、容量与隐私

`auth` 负责账号摘要与菜单，`messages` 负责收件箱和线程，组合根注入未读指示端口，两个 Feature 不循环依赖。网络操作携带账号 scope/session epoch；控制器另校验列表和线程请求代次。切类别、换会话、刷新会取消旧读取；账号变化和销毁取消读写并拒绝旧响应。登出清除私信草稿。

每个收件箱/线程最多 500 条，线程保留最新 500 条；游标不前进或空页停止加载。草稿最多保留 500 个会话。序号和游标一直使用十进制字符串/BigInt，不经过浮点数；线程使用序号去重，避免上游系统消息重复 `msg_key=0` 丢失内容。

私信、草稿不写 SQLite 或普通文件。私信图片使用临时内存图像，在销毁时驱逐解码缓存，不进入公开图片磁盘缓存；图片请求不附带账号凭据。没有新增自动遥测、消息 WS、后台轮询或桌面推送。未读数在登录后的首次读取、头像菜单打开、消息手动刷新，以及有未读消息的列表读取／已读回执成功后更新；切换已读分类不更新计数，不能视作实时推送。系统通知自动已读行为见下方 2026-10-25 补充记录。

## 2026-10-25：系统通知自动已读与共享未读数刷新

系统通知页面可见且列表成功呈现后，使用本次列表中最大的 `cursor` 自动确认已读。列表读取失败、空列表、缺失游标、工作区页面隐藏或请求已过期时不提交。游标独立于消息 ID、时间和分页字段，始终使用十进制字符串／BigInt，避免纳秒级数值丢失精度；仍沿用最近 20 条用户系统通知的读取范围。

补充端点：Web Cookie GET `message.bilibili.com/x/sys-msg/update_cursor`，参数为 `cursor/has_up=0/build=0/mobi_app=web` 与目标域 Cookie 中的 `csrf/csrf_token`，Referer 为消息站点。它虽使用 GET，仍按写操作仅发起一次，不自动重放网络失败／超时；沿用 deadline、取消、scope/session epoch 和重定向凭据保护。成功只校验响应业务码，允许空 `data`。失败保留未读数并提示刷新核对；同一列表的重建、角标刷新和隐藏后恢复都不重复提交，用户重新加载列表后才可再次确认。

回复我的、@我的、收到的赞仅在读取前该分类存在未读消息、列表非空且读取成功时刷新共享 `unreadMessagesProvider`；系统通知仅在原先存在未读消息且回执成功后刷新。私信显式已读成功时，仅原会话有未读消息才刷新计数，单纯发送消息不刷新。头像、账号菜单与消息分类数量共用此状态，无需再点击头像；切换已读分类不刷新计数。用户主动点击刷新按钮仍会重新核对未读数，私信仍保留显式“标为已读”按钮。

协议依据为 2026-10-25 读取的[官方消息中心](https://message.bilibili.com/)及其[公开脚本](https://s1.hdslb.com/bfs/static/2233-monorepo/message-pc/static/js/index.beee4580.js)中系统通知的 `handleItem/fetchList`：保留条目 `cursor`，首屏读取后向 `update_cursor` 提交最新游标。仅核对请求与字段语义，独立实现 Dart/Flutter，没有复制网站或参考客户端源码、资源；未执行真实账号写请求。

## 2026-10-25：收到的赞已读与头像同步
