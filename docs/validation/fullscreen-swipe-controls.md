# 播放器滑动调节亮度与音量

日期：2026-10-26。

2026-11-02 修复视频底层缩放识别器抢占画面滑动的问题，见 [Issue #58 原因与回归](touch-swipe-seek.md#2026-11-02视频底层手势抢占issue-58)。

## 行为与设置

- 视频、影视、直播及离线播放复用共享播放面板。普通／全屏画面左半侧纵向滑动调节亮度，右半侧调节播放器音量；向上增加，向下减少，并显示百分比。按下的位置决定本次操作，跨过中线仍保持原操作；滑过一个画面高度对应 100 个百分点。亮度范围 1%–100%，音量范围 0%–100%。
- 设置 → 播放与播放器设置均提供「滑动调节亮度和音量」，默认开启，关闭立即取消当前手势并恢复亮度。保存失败遵循原设置流程回退。原实现将 `preferences.v1` 快照版本增至 24；本次非全屏扩展保留 `fullscreenSwipeControls` 字段与现有快照版本，缺失或非法字段回退为开启，已保存的有效开关保留；数据库表结构不变。
- 仅触摸画面生效，鼠标拖动、横向滑动和控件区域保留原行为。纵向滑动与长按倍速参与同一手势仲裁；页面隐藏、播放源变化、应用失活、模态弹层或手势取消后不再接收旧手势更新。
- 音量复用 `PlaybackSession.setVolume`，沿用命令合并、播放源隔离和本次应用运行内的音量继承，不改写默认音量，也不改变播放、暂停、倍速或位置。

## 亮度边界

Android 通过 `WindowBrightnessService` 与 `WindowBrightnessHandler` 修改当前 Activity 的窗口亮度，不需要修改系统设置权限，也不改系统亮度。第一次覆盖时保存原窗口值（包括跟随系统的 `-1`），退出全屏、关闭开关、页面隐藏、切到后台或销毁时恢复；引擎脱离另有原生恢复。窗口命令携带 owner，旧窗口的清理不能覆盖新 owner；写入串行、滑动更新合并为一个待写值，原生读取和写入有 2 秒超时。快速松手可等待本次亮度读取完成，取消、切源、隐藏和弹窗会丢弃迟到读取。

其他平台使用仅覆盖播放画面的黑色遮罩降低画面亮度，控件保持可读，不修改显示器或系统亮度。退出全屏、关闭开关、页面隐藏或销毁后遮罩释放；iOS/macOS/Linux 的原生屏幕亮度调节不在本次实现范围。
