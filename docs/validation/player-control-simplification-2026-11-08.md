## 当前流程

`PlaybackSession → ConfigurablePlayerEngine → SharedPlayerEngine → 原生适配器` 分层保留。应用会话负责内容、账号、相对快进目标和有限恢复；共享层负责确认时间线、最新跳转和播放意图；适配器负责 SDK 命令、原生读取及缓冲证据。

1. **缓存交还原生。** 删除 `DashTrackBuffer`、`Mp4BufferIndex` 及专属测试。HTTP DASH 的原地址与允许的请求头直接交给 mpv／MDK，不再经本地 HTTP 代理、Range 分块重试、字节缓存和索引解析 isolate。普通点播两分钟、预览五秒，原生内存上限、背压、暂停和直播策略保留。
2. **时间线一个入口。** 事件和 250ms 采样统一处理原生位置与绝对缓冲终点；位置非负，已知时长时限制上界，缓冲终点限制在当前位置与时长之间。原生缓存可以缩短，不保留历史最大值，不通过码率推算时间。缓冲更新不会自行 seek 或改变播放意图。
3. **跳转队列有界。** 一个执行操作加一个最新待执行目标，取代逐请求追加的 Future 链。原生入口保留 40ms 输入合并；尚未下发的旧请求及时完成，已经开始的旧操作立即取消，下一目标等待原生退休屏障。同一取消只执行一次。打开、换源及暂停／停止不排在 seek 完成之后。
4. **预览与确认进度分开。** 沿用进度条和触屏局部预览，松手提交；相对快进从应用会话的最新目标累计。准备完成后按已知时长裁剪最终目标，只发布后端确认位置。跳转后重置旧缓冲范围，再接受新位置的原生端点；排队和执行期间的旧位置、EOF、普通失败事件不能覆盖新目标。
5. **同步保护保留。** 起播、跳转后继续和正常恢复仍在暂停中确认双轨。暂停意图、源代次、旧回调隔离、EOF 重播、健康检测、同内容停帧恢复与原生释放屏障沿用现有实现。

## 缓冲语义与行为变化

缓冲条现在表示后端实际报告的 demuxer 媒体时间。media_kit／mpv 提供主 demuxer 端点，不能据此声称外部音轨同样缓存完成；fvp 使用现有真实音频伴随管线的音视频原生剩余缓存较小值，播放信息面板也使用同一数值。两者均不表示数据已经解码、呈现或可保证无卡顿。

删除代理同时撤回了“应用在单轨静默两秒后从缺失字节无感续读”的机制。原生 SDK 自行读缓存；无法恢复时，仍由健康检测和应用会话预算暂停并恢复整组。两秒单轨活动检测、三十秒普通缓冲等待与网络续读是不同职责，没有增加新重试层。

本记录替代 D76 的代理／索引选择。[分轨续读](track-buffer-recovery-2026-11-08.md)和[缓冲显示与连续跳转](buffer-display-rapid-seek-2026-11-08.md)保留为历史，原生通过记录不代表本次通过。
