# 播放控件与小窗布局

日期：2026-10-05。在现有未提交工程上增量调整，未修改相邻参考仓库。

## 行为

- 常规工具栏保持单行，播放、弹幕输入、设置、清晰度、倍速、音量和全屏按钮垂直居中；全屏使用与其他图标相同的 40 像素按钮区域和 20 像素图标。
- 弹幕输入框随剩余空间收缩，默认最小宽度 200、最大宽度 420（Flutter 逻辑像素）；最小宽度跟随文字缩放增长。布局根据时间标签、可用清晰度、字幕和文字缩放计算需要的空间，不再在固定 1050 宽度拆成三行。
- 容纳不下完整工具栏时，参考用户提供的官方哔哩哔哩小窗截图，改为中央播放／暂停、可用时的前后分 P，以及底部单行时间、弹幕开关、发送入口、更多选项、音量和全屏。进度条继续位于工具栏上方；设置、清晰度、倍速和字幕选择均能从更多菜单访问。
- 小窗默认收起弹幕输入，点击发送入口可展开；收起时不接受键盘焦点。宽窄布局切换保留输入草稿，不自动发送。
- 普通视频页默认展开简介／评论，宽度足够时左右分栏，窄窗口中将信息放到 16:9 播放器下方；调整窗口大小不自动收起信息。通过画面右侧按钮或 W/F12 可手动收起／展开，收起后播放器占满可用高度，宽窄切换保留用户选择。隐藏信息区继续挂载，保留子标签和滚动状态。
- 布局切换沿用同一 PlaybackSession 和 VideoSurface，不重开媒体源，不改变进度、暂停或倍速。这里的小窗是当前应用窗口内的响应式布局，不创建独立窗口，也不新增系统 PiP、置顶或后台播放能力。

## 视频信息默认展开（2026-10-07）

- 原因：`VideoScreen` 原先将信息显隐初始化为未选择，随后根据 700 逻辑像素的宽度阈值决定默认值，导致窄窗口首次打开或未手动切换时自动收起简介／评论。现在显隐独立初始化为展开，宽度仅影响布局方向。
- 播放页 10 项控件测试通过，包含窄／宽窗口首次打开、跨 700／1000 宽度边界、手动收起后的宽窄切换、通过播放页命令展开，以及评论子标签和播放器实例保留；稍后再看队列与视频标签测试按默认展开行为同步调整。
- `tool/check.ps1 -SkipPub` 完整通过：根应用 989、`bili_api` 283、`bili_player` 22、`bili_danmaku` 32 项，共 1326 项测试；四部分格式与静态分析均通过。日志：`artifacts/video-info-default-check.log`。

## 移动端全屏方向（2026-10-07）

- 原因：移动全屏原先只隐藏系统栏，没有申请屏幕方向；通用播放快照也没有向应用暴露画面尺寸。
- `bili_player` 现在在当前源的 `PlaybackSnapshot.videoDimensions` 中提供经过像素宽高比和旋转元数据修正的显示尺寸。视频、影视、离线视频和直播共用的播放面板据此选择全屏方向：宽大于高时允许左右横屏，纵向或正方形画面使用正向竖屏。桌面继续使用原生窗口全屏。
- 首帧尺寸未知时保持进入时的屏幕方向，尺寸到达后再调整；全屏中换 P、换集、换线路或直播画面比例改变也跟随当前源。新源清除旧尺寸，未知尺寸期间保持已有全屏方向；同方向的进度更新不会反复调用系统旋转。命令沿用现有全屏 owner 和串行队列，关闭或隐藏页面后取消迟到方向更新，不重开播放器。
- 退出按钮、系统返回、隐藏或销毁播放页均释放方向限制并恢复系统默认旋转策略与页面系统栏。平台状态释放不依赖已销毁 Navigator 的 `push()` 完成，避免关闭页面后留下横屏锁定。
- 自动回归覆盖视频／直播横向、纵向、正方形画面，延迟尺寸、全屏换源、系统返回、隐藏／销毁、取消中的方向更新、暂停意图与单一 surface；播放器包覆盖显示尺寸、90／180／270 度旋转、缺失／无效元数据和新源尺寸清理。
- 在基于 `05c681f` 的独立检出中执行 `tool/check.ps1 -SkipPub` 完整通过：根应用 1204、`bili_api` 313、`bili_player` 32、`bili_danmaku` 52 项，共 1601 项；四部分格式与静态分析均通过。本次相关文件与主 worktree 的待提交内容逐文件一致；独立检出避开主目录同时进行的直播修改。日志：`artifacts/mobile-fullscreen-isolated-check.log`。
- Android API 36 手机尺寸 x86_64 模拟器的方向集成测试通过，视频和直播均覆盖横屏进入、全屏内切成竖屏、退出及竖屏重新进入，确认系统实际视口旋转且源 generation／打开次数保留。测试使用 fake engine 和真实 `WindowService`／`SystemChrome`，不作为原生解码或手机实机验收；日志：`artifacts/mobile-fullscreen-android.log`。用户随后要求测试通过后直接提交、不再构建，因此停止 Windows 原生回归的构建阶段，不新增 Windows／macOS／手机实机或发行构建通过声明。
- Android 16（API 36）及以上的宽度至少 600 dp 的大屏设备可能由系统限制方向请求；不绕过平台规则。依据：[Flutter 屏幕方向接口说明](https://api.flutter.dev/flutter/services/SystemChrome/setPreferredOrientations.html)。

## 全屏切换与控件显隐（2026-10-06）

- 视频、影视和直播共用的播放面板由页面保存控件显隐状态，普通视图与全屏视图共用该状态。双击画面进入或退出全屏时，隐藏的控件继续隐藏，显示的控件继续显示；全屏内单击改变的状态也保留到退出后。
- 默认“点击”模式下，单击画面仍切换控件显隐。全屏按钮、F 和 Esc 沿用同一状态；播放错误时仍显示控制栏，保留重试与设置入口。
- 回归测试覆盖鼠标／触摸、初始显示／隐藏、连续进入和退出、全屏内单击，以及媒体源、暂停位置和单一 surface 保留。Windows 原生用例增加鼠标双击在两种显隐状态下的进入／退出验证。

## 播放器控件交互设置（2026-10-07）

- 全局设置 → 播放，以及播放器配置 → 播放，共用“播放器控件交互”选项，支持“点击”和“动态”。默认“点击”保留原有行为：画面单击只切换控件显隐，鼠标悬停、等待和快捷键不自动改变显隐。
- “动态”模式下，鼠标移入或在画面内移动时显示控件，最后一次鼠标活动后静止 1 秒隐藏，移出画面立即隐藏。按住控件拖动或触摸长按倍速期间保持控件，结束后重新计时。
- 动态模式的点播（视频、影视、离线视频）单击画面播放／暂停，同时显示控件并开始 1 秒计时。直播单击画面不发播放／暂停命令，不切换控件，也不延后静止隐藏期限；直播控件显隐同样由鼠标移动控制。
- 双击画面仍进出全屏，不附带单击播放命令；普通和全屏继续共用显隐状态、播放会话和唯一媒体 surface。切回点击模式、隐藏页面、应用失去活动状态和视图销毁时取消动态定时器。
- `preferences.v1` JSON schema 从 15 升为 16，新增 `playerControlsMode`，缺失、未知名称或错误类型均回退为 `click`；SQLite schema 保持 3，保留其他偏好。
- Widget 回归覆盖 999／1000 毫秒边界、移动重新计时、移出立即隐藏、点播／直播与普通／全屏、鼠标／触摸单击和双击、直播单击不重置期限、按住控件及触摸长按、切换模式与隐藏／销毁、两个设置入口保存和旧配置兼容。
- `tool/check.ps1 -SkipPub` 通过：根应用 1286、`bili_api` 319、`bili_player` 32、`bili_danmaku` 52 项，共 1689 项；四处格式检查与静态分析均通过。日志：`artifacts/player-controls-mode-check.log`。
- 按用户要求本轮不构建、不进行原生或各平台实机验收；用户随后自行构建并验证真实鼠标交互。上方全屏构建和原生记录属于此前验证。
