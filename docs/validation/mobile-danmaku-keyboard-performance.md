# 移动端弹幕输入与键盘布局优化

日期：2026-10-10。优化前基线：`784f58f`。环境：Windows，Flutter 3.47.6 / Dart 3.13.5。

本次覆盖普通视频、全屏视频、影视和直播页面。键盘开合仍按当前可用高度调整画面、信息区和输入框；优化减少高度变化引起的重复构建、控件文字测量和直播弹幕缓存失效。下述数字来自可重复的 widget 结构探针，不能换算为实机帧率或掉帧率。

## 原因与实现

原先工作区在 `LayoutBuilder` 中调用缓存页面的工厂，播放页又在高度敏感的布局回调中创建播放器、简介、选集和聊天内容。每次键盘 inset 更新都会向这些子树传递新 widget，即使宽度和业务状态没有变化。共享播放器同时重新测量时间、倍速和清晰度标签；直播弹幕的 `setViewport` 还会清空活动项与文字/图像缓存。

现在工作区和直播页面在几何布局回调外创建内容，布局回调仅调整其尺寸和位置。视频、影视及共享播放器使用 `WidthLayoutBuilder`：宽度变化、widget 更新或已声明的 inherited 依赖变化时重建内容；仅高度变化时继续以最新约束布局现有子树。高度相关的计算留在内层 `LayoutBuilder`。该组件基于固定 Flutter SDK 的公开布局接口，并覆盖命中测试、文字基线、零高度和非固定高度布局。

共享播放器仅保存最近一次控件尺寸计算结果，输入包括宽度、时长格式、倍速、清晰度标签、发送/字幕/原声入口、文字样式、方向和缩放。位置更新及键盘高度变化不会重复排版；真实标签和排版配置改变时重新测量。测量使用的 `TextPainter` 仍立即释放。

直播弹幕尺寸变化沿用文字排版和图像缓存，保留活动 ID、原始时间与去重状态。有效显示区缩小时只移除放不下的轨道，增大时不会重播已移除项；零尺寸过渡不消耗待处理消息，恢复后仍按直播单调时间过期。滚动项按原进度投影到新宽度，固定项按新显示区定位。字体、效果、配置变化和控制器销毁继续沿用原有失效与资源释放规则。点播和直播绘制层显式依赖 MediaQuery 的 DPR，逻辑尺寸不变的换屏也会更新图像清晰度。

## 结构对比

使用同一批脱敏 fake repository/player，模拟 Android。每个场景执行 16 次键盘弹出及 16 次收起的 inset 更新，每次 pump 16 ms；这是测试推进间隔，非帧耗时测量。竖屏逻辑尺寸为 390×844，影视/直播另覆盖 844×390 横屏及信息区开/关。

## 验证边界

按用户要求，本次仅优化、检查并提交，应用构建与打包由用户执行。未运行 Android 实机、Windows 原生播放或 macOS 构建/运行，也未执行真实账号发送。widget 探针证明重复工作减少及状态/布局保留，尚未证明设备上的 UI/raster 帧耗时改善。

直播探针用不含 SC 的聊天 fixture 隔离键盘路径。前期带 SC 的横屏极小可用高度探针发现原有溢出，本次没有修改该布局边界；常规 SC 功能测试仍通过。真实设备复测应包含 SC、表情和较大字体。

手动构建后，建议在 profile/release 中对普通视频、影视、直播的横竖屏及全屏各反复弹出/收起键盘，观察输入框跟随、草稿、焦点、弹幕连续性和播放状态；同时比较 UI/raster 帧耗时与超过设备刷新预算的帧数。真实输入法动画、视频纹理缩放及系统合成仍需以设备测量为准。
