# 播放地址内容不可用重试

日期：2026-11-05。针对部分视频偶发出现“当前内容暂不可用”的反馈，补充原有网络重试未覆盖的内容错误恢复。未取得出错视频及当时的在线响应，不能据此确认原始故障的业务码或服务端原因。

## 行为与边界

- 端点保持 `api.bilibili.com` Web GET `/x/player/wbi/playurl`，Cookie 可选、WBI 签名、JSON 响应，无分页；请求身份、画质、语音及鉴权语义不变。
- `getPlayInfo` 与 `getVideoPreviewInfo` 缺少 DASH、缺少视频轨、完整播放缺少音频轨，以及未分类业务错误，在权益核对后仍为 `unavailable` 时自动重试。每次方法调用最多发送 3 次 playurl 请求，包括首次；网络／超时、HTTP 500／502／503／504 和 WBI `-403` 重签都消耗同一额度。
- 沿用约 200–299 ms、400–499 ms 的指数退避及抖动。每次网络读取最多 2 秒，全部读取、权益诊断、WBI key 获取与退避共用同一 deadline。应用层仍为 25 秒；独立调用 API 包且未传 deadline 时，使用包的单次操作默认总预算 12 秒，不在重试时续期。
- 首次失败才读取详情核对权益，该逻辑读取在本次方法调用中最多发起一次并复用结果，详情传输沿用既有网络重试；成功返回完整 DASH 时不增加详情读取。未授权充电／付费视频、完整播放的试看、明确的认证／权限／删除／风控、HTTP 非重试状态及协议损坏均不触发新增内容重试。诊断详情自身失败时不将其误当作 playurl 错误重放。
- 保留取消和 account/session epoch；取消中断退避，账号代次变化后不得再次发送旧账号的 playurl 请求。耗尽次数后保留最后一次失败类别、业务码或 HTTP 状态，由既有 UI 显示错误。
- 悬停仍允许仅视频轨，并可使用合法试看。UGC 下载沿用同一解析入口；PGC、直播、媒体 CDN、原生播放器及账号写操作不受本次逻辑影响。未新增依赖、设置或日志字段。

## 验证

- 新增[播放地址重试测试](../../packages/bili_api/test/playurl_retry_test.dart)，用 fake transport/session/clock 验证缺轨恢复、未分类业务错误恢复与最终错误、网络／HTTP／WBI 共享次数、权限／风控／删除／试看／协议错误不重试、悬停视频轨语义、退避中取消／换账号及显式／默认 deadline。
- 新增用例在旧实现上首先复现缺轨时直接失败；修改后新增 39 项，与既有权益、网络重试测试共 76 项通过，日志 `build/playurl-unavailable-retry-targeted.log`。API 包 `dart analyze` 通过。
- `tool/check.ps1 -SkipPub` 全量通过：根应用 4112、API 586、播放器 148、弹幕 161、封装 5，共 5012 项测试通过，格式、静态分析与打包边界检查通过；日志 `build/playurl-unavailable-retry-check.log`。根应用 13 项沿用既有条件跳过，另有 10 项 mux 原生测试因未设置 `BILI_MUX_LIBRARY` 跳过，不能算作原生集成通过。最终 API 代码另行 `dart analyze` 通过；改动文档的 310 个本地链接与 `git diff --check` 通过。
- 本轮不改原生播放实现；未进行在线故障复现、三端实机播放或性能测量。
- 热重载已尝试，但 DTD 未发现正在运行的调试应用，未完成热重载；本轮验证以 CLI 分析和测试为准。
