## 行为和协议

- 他人主页更多菜单的“举报”在应用内打开表单；游客先进入现有登录流程。本人主页不显示举报入口。表单显示目标名称及 UID。
- 举报内容至少选择一项：头像违规、昵称违规、签名违规；可以多选。举报理由可不选，六个理由单选，再点已选理由可清空：色情低俗、不实信息、违禁、人身攻击、赌博诈骗、违规引流外链。
- 显式点击“提交举报”才发送 `POST https://space.bilibili.com/ajax/report/add`，profile 为 Web Cookie，使用 form-urlencoded，参数 `mid`、`reason`（内容编码 1–3，排序后逗号分隔）、可选 `reason_v2`（理由编码 1–6）和当前目标域的 `csrf`。不使用 WBI/App token，无分页。
- Cookie/CSRF 必须匹配 `space.bilibili.com` 的域、path、secure 与有效期；`Origin` 为空间站点，`Referer` 为目标空间。传输复用既有禁止重定向的写请求通道，参数只编码一次，UID 全程为字符串。
- 该端点使用旧式 JSON `status` 包装，仅布尔 `true` 视为提交成功。`false` 为拒绝，缺失/畸形字段为协议错误；兼容带 `code` 的认证或风控拒绝，不将 `code=0` 单独当作举报成功。服务端原文不进入错误消息或日志。
- 单次写入复用 `ApiRequests` 的 25 秒总 deadline 与客户端单次超时预算，均不自动重试。提交期间禁用表单和提交按钮；成功关闭表单并提示“举报已提交”。超时、断网、协议错误或未知异常的结果不明时，保留表单提示“举报结果未确认，请勿重复提交”，本次表单不再允许提交。
- 控制器固定表单打开时的账号 scope/session epoch；提交前、完成后均核对，账号变化取消请求，迟到结果不能提示成功。关闭弹窗释放控制器并取消未完成请求；主页拥有单独的取消信号，关闭主页也会立即取消，即使根 Navigator 上的弹窗仍然存在。选择内容在创建请求时复制为不可变集合。
- 表单使用有界宽度、可滚动内容和可换行的理由选项，适配窄屏、横屏和大字体，继续使用共享应用对话框的窗口/模态隔离。
