# 缓冲条缺失与连续跳转失败

**历史记录：** 代理／字节索引及逐请求跳转队列已由[播放控制流程简化](player-control-simplification-2026-11-08.md)替代。原生同步、EOF 与取消屏障继续保留；本文的构建与实机结果不代表后续实现已验收。

日期：2026-11-08（Asia/Shanghai）。补充并修正[分轨缓冲续读记录](track-buffer-recovery-2026-11-08.md)的缓存显示与 seek 边界。

## 定位与修复

- 用户 Windows Release 的本地脱敏日志显示后端为 fvp，16:10:51 在约 226 秒处检测到音频活动停滞，恢复后发生视频中断，16:11:01 在约 325 秒处再次失败。这些日志没有记录完整的 seek SDK 返回码，不能单凭日志认定每次失败同根因。
- 缓冲条原先把中转字节缓存当成原生播放器缓存。中转缓存淘汰后，即使 SDK 仍持有包，也会把共同终点压至播放位置；未知索引同样被当成零缓冲。现改用已经交给 SDK 的合并字节范围，最多保留 256 段元数据，与有界重试字节缓存分开。已知轨道按 MP4 时间索引取连续终点，并由原生窗口限制上界；未知索引保留原生信息，不按码率猜时间。已知缺口仍会缩短共同终点。源释放时一同释放范围信息，不写磁盘。
- 补充定位到 MP4 `moov` 将大量音频采样放在同一 chunk 的情况：seek 可从 chunk 内部采样开始，旧整块覆盖判定会把实际已有的缓冲判为零。现按 `stsz`／`stts` 的真实采样大小与时间建立范围，保留原有元数据容量上限，不要求已跳过的前半个 chunk。
- 空或不支持的 fragmented `moov` 不再阻止读取后面的有效 `sidx`。并发 Range 留下的短重叠块不再遮住较早块的剩余字节。
- 720 秒受控 HTTP DASH 连续跳转复现了两后端的失败：取消 seek 后，中转层仍保留旧 HTTP 读取，达到 8 路上限后向新目标返回 404；fvp 的重准备得到 `-6`。取消原生 seek 现在同步撤销对应读取，释放并发名额、终止上游请求与重试，并通过响应 deadline 结束可能正在 flush 的本地 socket。待收尾任务仍由源关闭屏障等待；保留既有索引、实体身份和可复用字节。
- 原生取消现在有完成屏障，先退出旧 demuxer，再关闭旧 HTTP 读取；新目标等待同一屏障。原生入口合并 40ms 内连续进度输入，尚未派发的目标只执行最后一次；已经开始的 seek 立即取消。源替换隔离旧取消结果。
- fvp 所有输出路径都等待真正的原生暂停确认；seek 期间屏蔽旧状态回调。准备、反向和未缓存目标不再使用 `InCache` 标志；[MDK 的标志契约](https://github.com/wang-bin/mdk-sdk/wiki/Types#enum-seekflag-flags)限定它只用于已经缓冲的前向区间。HTTP 重准备的 `-8` 返回也纳入原有最多两次的恢复尝试，不增加总 deadline。共享恢复播放门在暂停中重新等待双轨就绪；后续已移除静音预跑，fvp 音频通过真实音频管线的原生 seek 完成确认，视频跟随音频原生时钟。现行边界见[双轨同步屏障](paused-pair-synchronization-2026-11-08.md)。seek 的音频确认使用本次操作预算。失败诊断只增加数字 SDK seek 返回码，不记录原始异常、地址或凭据。
- media_kit 对可能排队延迟的 completed 事件查询当前原生 `eof-reached`，并核对源与 seek revision；旧负载的结束事件不能撤销新目标的播放意图。查询有超时，不阻塞事件循环。
- 组合回归进一步定位到 fvp 片尾竞态：对外屏蔽 seek 事件时仍须记住原生 EOF。否则停在最后一帧的播放器无法响应下一次 pause，最终超时。现保留内部 EOF 事实，暂停等待根据异步 stopped／EOF 证据返回未确认，交由 seek 的有界重准备处理。常规 pause 不调用额外的同步 `waitFor(Stopped)`，避免阻塞同一 Dart isolate 的 HTTP 服务。
- 片尾连续重复还确认了调用顺序问题：共享 seek 不再先调用普通 pause，而由后端 `seekTo` 负责适合该 SDK 的暂停／EOF 退休；fvp 原有 seek 协调器可直接进入有界重准备，media_kit 在其 seek 内确认暂停。输入合并等待期间的旧 EOF 不撤销已请求的新目标；真正执行 seek 后的正常 EOF 仍照常生效。

## 原双轨屏障改动前的验证

以下为缓冲／取消修复阶段的记录，后续取消静音后的验证以[双轨同步屏障](paused-pair-synchronization-2026-11-08.md)为准。

- 新增行为覆盖：中转缓存淘汰后保留已交付字节、已知缺口、未知索引、fragmented moov 后的 sidx、连续 12 次撤销读取后的并发名额、原生退休屏障、40ms 输入合并，以及 seek 后重新确认音频。
- [长视频连续跳转](../../integration_test/windows_dash_rapid_seek_test.dart)：两后端 × 播放／暂停，在 720 秒 HTTP DASH 中每轮先启动可能等待网络的 650 秒 seek，再以 20ms 间隔改目标，三轮后均要求停在最后的 325 秒、保留播放意图与 generation，并继续正常播放、显示正缓冲。
- 首轮组合回归 44/45 项通过，片尾自动播放项失败；独立复跑有波动。补充数字诊断与多轮片尾回归后定位并修复上述 EOF／pause 竞态，最终结果如下。

- 格式、根脚本 Lint 阶段、根应用与 `bili_api` 静态分析通过；最终两处原生边界也经 Dart MCP 定向分析无错误。根应用 4726 项通过、13 项沿用符号链接条件跳过；API 719、播放器最终 352、弹幕 161、mux 5 项通过。mux 10 项原生测试因未配置 `BILI_MUX_LIBRARY` 跳过。
- Windows 两后端前向窗口 2、独立分轨续读 4、seek 同步 18、重播 6、启动 9、中途音视频 EOF 恢复 4 项通过。缓冲条在初始、暂停、推进和 400 秒 seek 后均为正、服从约 120 秒原生窗口；fvp 示例为 `positionMs=400510`、`bufferedMs=520531`。
- 长视频连续 seek 四种状态通过，包含待网络数据的旧目标和三轮输入。57 项组合重复中的一次片尾自动播放仍因共享层先普通 pause 而超时，未将该组合记为全通过；将暂停／EOF 退休移入后端 seek 后，最终独立连续 5 轮、共 10 项片尾回归全部通过。已有通过项不替代此后针对变化分支的验证。
- 最终 Windows Release/AOT 受控入口 `.dart_tool/rapid_seek_release_probe.dart` 四项通过，共提交 120 次 seek 请求；两个后端分别从播放／暂停状态连续改目标，均保留最后的 325 秒和意图，随后推进到约 328.8 秒，共同缓冲到约 448.6–448.8 秒，无失败或换 generation。结果为 `build/validation/buffer-seek-release-result.json`；这里只使用 720 秒本地素材的回环 HTTP，音量为零，没有初始化账号或数据库。
- 临时双后端 Debug 入口经 DTD 热重载成功、无运行时错误；完成播放器和 HTTP 服务释放后退出。原生视频释放、渲染队列和尺寸 C++ 回归 9 项通过；346 个本轮文档相对链接及 `git diff --check` 通过。

验证后已执行 `flutter build windows --release -t lib/main.dart`，恢复普通入口的完整 Release 目录；入口为 `build/windows/x64/runner/Release/bilisail.exe`，`data/app.so` 为 16,663,432 字节。没有把受控验证入口留作日常运行构建，也未安装或改动正在运行的正式应用。

本轮针对 Windows 的受控本地媒体和 HTTP 服务；真实 CDN、人工听音画同步、长时间播放与性能未作为这些测试的结论。Android、macOS、iOS、Linux 的实际设备播放未验证。
