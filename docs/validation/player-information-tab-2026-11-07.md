# 播放器设置实时播放信息

日期：2026-11-07（Asia/Shanghai）。播放器设置增加第五个标签“实时播放信息”，视频、影视、直播、离线和听视频沿用同一入口与当前播放会话。原有四个设置标签及索引不变。

信息页顶部提供“复制全部信息”，滚动时保持可用。复制点击时显示的完整快照，包含全部分组、参数、单位、缺失值占位及说明文字；界面与文本共用同一份格式化数据，不额外触发采样。复制成功／失败通过应用提示反馈。

## 展示内容

| 分组 | 参数 |
| --- | --- |
| 播放状态 | 当前实际后端、播放状态与意图、媒体类型、播放模式、清晰度、位置／时长、倍速、音量、缓冲／跳转 |
| 视频与输出 | 编码、实际硬解、解码／显示／输出尺寸、源帧率、估算滤镜输出帧率、实时／标称码率、像素／硬解底层像素格式、色彩矩阵／范围／原色／传递函数、输出驱动、解码与输出就绪状态 |
| 音频 | 编码、实时／标称码率、采样率、声道数、均衡增益、输出驱动、解码就绪状态 |
| 缓存与同步 | 缓冲终点及剩余媒体时间、原生缓存时长／大小／读取速度、A−V 差、音／视频时钟、输出／解码累计丢帧 |

原生属性含义与单位按 [mpv 官方手册](https://mpv.io/manual/stable/#properties) 核对：码率为 bit/s，缓存速度为 byte/s，音画差从秒转换为毫秒。`estimated-vf-fps` 是滤镜链输出按媒体时间戳估算的帧率，不等同于 Flutter 实际合成帧率；缓存速度只表示当前主解复用器读取，不代表设备总网速或 DASH 两轨合计。累计丢帧随原生媒体源重建而重置。

## 数据与生命周期

- `bili_player` 公开可选只读 `PlayerInformationSource` 与不可变 `PlayerPlaybackInformation`。不扩展基础播放命令接口，不创建第二个播放器。
- `MediaKitEngine` 仅按固定属性白名单异步取值；单个属性最多等待 1 秒，未提供、失败及非法值保留为空。只允许有限长度的编码／驱动／色彩标识及有限数值通过，不展示 URL、请求头、路径或轨道 ID，也不新增日志／遥测。
- `ConfigurablePlayerEngine` 转发当前实际后端，并映射到外层源代次。更换或关闭后端后丢弃旧采样。`FvpEngine` 提供实际 MDK 后端与均衡增益，其余尚未开放的原生参数显示“—”；共用播放状态与源标称参数仍可查看，不将设置中的后端／解码偏好当作当前实测值。
- 应用层 `PlaybackInformationController` 从当前 `PlaybackSession` 读取媒体与状态，串行采样，约每秒局部刷新一次；界面不直接访问 media_kit。源／账号／快照代次不匹配的异步结果不能发布。
- 只在信息标签可见且应用处于前台时采样；离开标签、进入后台或关闭弹窗后停止。关闭后迟到回复不能更新已销毁的组件。
- 宽屏使用参数／值两列，窄屏改为上下排列，所有内容在固定设置弹窗内滚动；不持久化任何采样。
