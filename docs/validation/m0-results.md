## 首版边界

已建立 app 组合根、feature 分层和三个独立包。页面只通过应用控制器及领域模型访问数据。首页采用真实热门端点，支持分页、搜索、视频详情、分 P；UWP 的白底、粉色强调、封面网格、侧栏和视频详情分栏作为视觉参考。没有复制 UWP 图标或源码。

观看能力为 H.264/AAC DASH、暂停/seek/倍速/音量/可用清晰度/全屏、普通弹幕与字幕 cue。本地历史按账号 scope 隔离，保留后退 seek；设置和历史使用 SQLite。登录代码提供 Web QR、nav 校验、恢复、退出与系统安全存储；尚未由真实账号完成扫码闭环。不会自动投币、点赞、发送、上报云历史或遥测。

字幕索引在线样本为空；正文显示只通过人工 fixture 验证，不能声称已验证登录后字幕。首页没有伪造的推荐和分区数据。直播、PGC、下载、云收藏、后台音频、PiP 和多窗口播放尚未实现。

## Windows 原生测试

命令：`./tool/test-windows-media.ps1 -Online`，使用 `integration_test/windows_playback_test.dart`，测试启动真实 Windows Flutter runner 和 media_kit 原生库。早期三项曾 **3/3 通过**；加入全屏回归后的一轮为 **3 通过、1 失败**：首个公网 CDN 视频地址在 35 秒内未就绪，受控媒体、系统存储和六次全屏往返均通过。在线测试随后改为经过实际 PlaybackSession，覆盖应用已实现的有限备用地址逻辑；不能把首次超时从记录中抹去。

最终通过实际应用会话的复测为 **4/4 通过**，真实游客样本仍为 `BV14sHj62EzS`，quality 32，视频 852×480、音频 2 声道/44,100 Hz。该次原生测试播放阶段约 11 秒；这只是一次测试运行时间，不是启动性能基准，也未证明该次实际触发过备用地址。

1. **受控分轨**：本地 HttpServer 只允许预期 Referer/UA，音视频分别经 302 到最终媒体；两路观察到 `Range: bytes=0-`，服务器回 206/Content-Range。最终视频 320×180、音频 1 声道/48,000 Hz，确认位置推进。暂停 700ms，位置变化小于 300ms；seek 至 7 秒、倍速 2；重建 surface 不改变 engine generation；stop 后可重开和释放。
2. **系统存储**：使用随机隔离 key，通过 SystemCredentialStore 的双槽写入、覆盖、读取与删除，不使用真实 Cookie；测试结束清理 probe。
3. **真实游客 UGC**：同一 session epoch 下调用热门/详情/playinfo，再由 native 分别拉取两路 CDN；解码参数为视频 852×480、音频 2 声道/44,100 Hz，位置推进且 seek 至 10 秒成功，随后暂停、停止并释放。
4. **实际全屏与 Esc**：真实原生播放器打开本地独立音视频文件，启用语义树后执行六次窗口全屏/Esc 往返；检查 engine generation 不变、无 Flutter 异常，并在最后恢复窗口和释放会话。这不等于外部 UIA 客户端压力测试。

这里的音频结论来自解码后参数，不以“视频 URL 可打开”代替。自动化尚未量化音画偏移、输出设备声压或长时间同步，因此不能扩大成完整音画同步认证。

### 调试中发现并修复

- API 封面含 `http://`：仅对已知 B 站图片来源转换 HTTPS，恢复真实封面；其他不可信 URL 仍拒绝。
- native 打开返回早于 `on_load`：过早附加音轨会使外部音轨丢失头。已等待视频轨就绪再附加音频，并在播放时等待解码音频参数，超时明确失败；受控用例由失败转为通过。
- 短视频预取不存在的下一弹幕段：现在按已知总时长截断预取，预取失败不抢占当前播放错误提示。
- 快速换源/清晰度、旧 stop 与进度保存竞态：加 generation/所有权检查与 fake engine 行为验证。
- 连续设置修改：界面立即反映最新值，保存串行执行，旧完成不能覆盖新状态，失败不阻断后续保存。

### Windows 辅助功能兼容性风险

在便携 Release 的全屏/Esc 验收中，曾出现一次进程崩溃（2026-10-05 13:13，本地时间）。Windows 事件记录 `flutter_windows.dll` 的 `0xc0000005`，随后包装为 `0xc000041d`。两个本地 dump 使用匹配的 Release DLL/PDB 分析，可信栈是 `AXPlatformNodeWin::get_accName` → `AXNodeData::HasStringAttribute`，定位到辅助功能客户端读取控件名称时访问无效属性向量；不能据此确定节点由谁释放，也不能归因为媒体解码器。

后续同一旧版本进程在关闭和开启 UIA 文本读取的情况下均有成功往返，说明问题是间歇性的。应用增加退出全屏前释放焦点、等待帧结束、阻止重复退出，以及为播放器聚焦节点提供固定无障碍名称的防护；保留进度条和按钮各自的无障碍语义。新增原生六次全屏/Esc 往返回归，但有限重复通过不能证明 Flutter 原生辅助功能崩溃已经根治。此风险保留为首版已知限制，需继续在读屏软件、多显示器和频繁换页条件下验证。

防护后的最终便携 Release 于 13:26 再次直接启动：真实视频从本地进度继续，播放与弹幕可见，外部 UIA 文本读取开启时连续三次全屏/Esc 往返通过，最后回到首页停止播放；该轮未产生新的应用崩溃事件。原生集成六次往返和此次 Release 三次往返是两组不同证据，均不作为长期稳定性承诺。
