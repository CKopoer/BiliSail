# 首页刷新、自动分页与图片缓存

日期：2026-10-05。本轮在用户已有未提交工程上增量修改，工具链仍为 Flutter 3.47.6 / Dart 3.13.5。

## 列表交互

首页频道及所有子标签使用右下角竖排方形操作按钮。刷新按钮常驻，回到顶部仅在当前列表离开顶部后出现；刷新当前频道/子标签并回到顶部。动态的全部、视频、图文，以及视频动态、番剧、国创、直播、放映厅、收藏等子标签统一移除底部“刷新列表”，保留分页失败的显式重试和手动加载更多。需要登录的列表仍先显示登录入口。

首页可分页列表共用滚动检查：首屏内容布局完成、内容改变、窗口尺寸改变、恢复可见和向下接近底部时，都检查剩余滚动距离。距离底部不超过 600 逻辑像素时补页，因此刚进入推荐或窗口变大时无需先滚动。控制器仍负责单飞、代次隔离、分页去重及请求取消；错误页不自动重试。隐藏的首页频道/子标签与非活动工作区标签不触发自动分页，各列表保持独立滚动位置。

图文动态在服务端返回的全部动态中筛选，空页并不代表没有后续内容。Feed 连续两页、Home 连续三页无新增内容时暂停自动请求并提示手动继续；预算计入空首屏，手动重试重置预算，仍保留服务端 `hasMore`。成功读取的页码/游标保留；动态游标缺失、不前进或循环时不推进请求进度，等待重试原请求。列表按稳定 ID 去重，动态单个子标签仍最多保留 200 条。

## 图片缓存

设置新增“缓存”分类和默认开启的“缓存图片”。同一个图片 URL 使用共享图片提供器，频道切换可以复用已解码图片；本地文件缓存用于解码图片被淘汰或应用重新启动后的复用。开关保存在现有设置快照中，旧设置缺少字段时使用开启默认值，不清空数据库或其他设置。

图片缓存由 app 组合根持有，通过共享 UI 注入，core 不依赖设置 feature。推荐与视频动态封面统一按 640 像素宽解码；头像 96 像素，富动态卡片保留尺寸约束，缩略图解码最大边 1280 像素。相同 URL/解码尺寸共享图像流，不同尺寸共享原始字节下载。点击后的原图预览采用下述独立限制。

| 项目 | 默认边界 |
| --- | --- |
| 磁盘缓存 | 最多 512 张、总量 64 MiB、7 天有效期，按最近使用时间淘汰 |
| 解码保留缓存 | 最多 256 张、64 MiB；正在显示的图像流仍由 widget 持有，该限额不是整个页面的内存上限 |
| 图片传输 | 单图最多 4 MiB，6 个并发、最多 64 个任务，15 秒 deadline |
| 目录与元数据 | 系统缓存目录 `public_images_v1/<sha256(scope)>/<sha256(fullURL)>.img`；文件头仅保存创建时间与内容摘要 |

### 标签切换与封面队列修复

2026-10-06 使用真实 `FeedScreen` 子标签与分页组件、模拟慢图片下载复现：两组标签各加载两页后共挂载 80 张封面，原实现一次请求所有封面，64 个任务被接受、16 个因队列满直接失败；前面的任务完成后失败封面仍未补载。`IndexedStack` 保留隐藏页，隐藏自动分页与图片请求的生命周期不同，旧页请求继续占用共享队列。

共享 `AppNetworkImage` 现在按所属滚动视口决定是否解析图片，预取范围为视口四周 160 逻辑像素。滚动、布局、窗口尺寸和工作区/子标签活动状态变化后合并执行可见性检查；隐藏页与屏幕外图片不发起新请求，并释放 widget 的图像流监听，已发起的共享下载正常收尾。原有卡片 `Wrap`/`Column` 布局、列表内容与滚动位置保持原实现；本次是图片延迟加载，不是列表卡片虚拟化。

任务容量仍为 64、下载并发仍为 6。队列满使用独立的 `ImageQueueFull` 错误类型，可见图片监听容量释放事件后重新解析，不用定时轮询，也不把等待者加入传输队列。完成或失败的任务都释放容量；隐藏、换 URL 或销毁组件时解除等待订阅。HTTP 拒绝、解码错误等真实失败仍走原错误占位，不因容量事件被自动重放。封面及头像占位改为依据第一帧是否就绪，不依赖自定义提供器未发送的下载进度事件。

新增 9 项回归覆盖屏幕外延迟请求、滚回缓存复用、窗口扩展、嵌套视口内外滚动、固有尺寸测量、拥塞后无需重挂载的自动补载、隐藏工作区停止等待、真实传输错误不重放与首帧占位。真实子标签切换/分页回归在缓存开启和关闭两种设置下施加小容量队列压力，验证可见封面全部恢复及滚动位置保留。验证使用 fake loader，不使用真实账号。

最终 `tool/check.ps1 -SkipPub` 通过：根应用 527、bili_api 172、bili_player 16、bili_danmaku 10 项测试，共 725 项；四处格式与静态分析通过。`flutter build windows --profile --no-pub` 成功，输出 `build/windows/x64/runner/Profile/bili_lite.exe` 及配套文件。未操作真实客户端完成本次慢网 UI 验收，Android/macOS 未实机验证；当前运行的 Release 进程没有自动重启，需运行新构建才能使用修复。

### 动态大图加载修复

2026-10-05 对用户截图中的同一条环球科学图文进行只读诊断：原始 PNG 为 2560×1707、4,832,946 字节，CDN 返回 HTTP 200；原图超过上述 4 MiB 单图传输上限，`loadPublicImage` 在解码前拒绝响应，因此卡片显示破图。Flutter 的 `cacheWidth` 只控制解码尺寸，不能减少原图下载字节数。

动态卡片中的静态图片现在按显示用途请求公开 `hdslb.com` CDN 缩略图：单图 960、网格 520、视频封面 480、链接封面 256 像素宽。使用 `@<width>w_1280h_0e.webp` 保持比例、限制宽高、不裁剪；实际复测该单图得到 HTTP 200、960×640、59,520 字节，并在 Windows Profile 原生 Flutter 引擎中成功解码。4 MiB 缩略图上限和其余缓存配额保持不变，缩略图各尺寸按自己的完整 URL 缓存；领域模型仍保留原图地址。

只改写无 query/fragment、无已有 CDN 变换参数的 JPG/JPEG/PNG/WebP 地址；GIF、已有变换、签名参数、其他主机和协议保持原地址。动态行内表情沿用原图片流。此规则在共享动态卡片中生效，覆盖首页、空间及转发内容。只读诊断只打印尺寸、响应字节数、HTTP 状态、格式与解码结果，不输出或保存正文、账号 ID、图片 URL 或凭据；本次未触发账号写操作。

点击卡片后打开独立原图预览，直接请求原图地址，不使用缩略图缓存或 1280 像素解码上限。预览只保留当前图片，原图下载最多 32 MiB、30 秒 deadline；解析头部后验证最大边 16,384 像素、总量 32 Mi 像素，再交给 Flutter 解码。请求不携带凭据，保持原有 Referer、HTTPS/重定向约束，不写磁盘。切图、关闭及账号会话变化会取消请求并隔离迟到响应；切图/关闭清除原图的解码缓存。

预览参考 UWP 的 [ImageViewerControl.xaml](../../../biliuwp-lite/src/BiliLite.UWP/Controls/ImageViewerControl.xaml) 和 [ImageViewerControl.xaml.cs](../../../biliuwp-lite/src/BiliLite.UWP/Controls/ImageViewerControl.xaml.cs)，自行编写 Flutter/Riverpod 实现，未复制 C#/XAML 或资源。默认适应窗口，工具栏支持原始大小、放大/缩小、比例显示和上一张/下一张；鼠标拖动、Ctrl+滚轮、触摸缩放、方向键/PageUp/PageDown 和 Esc 可操作。用户本轮要求暂不提供复制图片或保存图片，相关按钮、服务、原生通道及专项测试均已移除。

新增行为回归验证列表先加载缩略图、点击后才加载原图，超过 4 MiB 的原图可以使用独立额度；覆盖下载单飞、切图/关闭/账号变化取消、迟到响应、超时重试及边界地址不改写。预览组件测试在 1100×740 和 360×640 验证缩放、图片切换、键盘关闭及无溢出。在线证据为截图中真实样例的 Windows 原生请求验证；当前已打开的旧客户端未自动替换，Android/macOS 仍未实机验证。

删除复制/保存后的最终验证：`tool/check.ps1 -SkipPub` 通过，根应用 421、bili_api 120、bili_player 16、bili_danmaku 10 项测试，四处格式/静态分析通过。原图仓储在线读取同一样例得到完整 4,832,946 字节、2560×1707，未替换为缩略图。Windows runner 的原生文件恢复本轮修改前的内容，无新增依赖或系统剪贴板操作；正常应用使用 `flutter build windows --profile --no-pub -t lib/main.dart` 构建。

设置快照 JSON `schemaVersion` 从 4 升为 5，新增 `cacheImages`，SQLite 表结构及数据库版本仍为 1。设置尚未读取完成时关闭缓存，随后使用实际保存值。关闭后不为新图片读取/写入缓存，普通 rebuild 和当前已显示的图片保持原图像流；关闭不会立即删除旧文件。过期/损坏缓存重新请求，缓存目录不可写时正常显示网络图片。已接入的首页封面、共享头像和富动态中的 B 站公开 HTTPS 图片采用上述缓存；其他合法 HTTPS 图片沿用网络图片提供器，不写入这套磁盘缓存。

缓存按账号 scope 隔离；退出、切账号或 session 失效取消旧图片请求并清旧私有目录，迟到响应不得回写。文件名不落盘 URL/query 或账号 ID；图片传输不接收 Cookie/Authorization，保留系统 TLS 验证。新增直接依赖仅为此前已有锁定的 `crypto 3.0.7`，用于摘要键与内容校验，不增加原生二进制。
