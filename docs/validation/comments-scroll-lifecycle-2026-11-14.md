# 评论区滚动生命周期复查与优化

日期：2026-11-14；源码基线 `dbbf5f4d`。覆盖视频、影视和动态共用的 `CommentsPanel`、主评论、楼中楼及回复预览。接续[上一轮组件复用优化](comments-performance-2026-10-30.md)，本轮定位滚动期间的请求、帧后回调和手势资源，没有修改协议、写入规则或 500 条容量。

## 定位结果与处理

| 路径 | 问题与影响 | 处理 |
| --- | --- | --- |
| 正文及回复预览的行内表情 | 仍使用 `Image.network`，绕过应用图片队列、字节缓存和可见性取消。滚动缓存区或保留页面中的表情不能随视口释放未完成的共享请求，也没有应用图片组件的屏幕外帧释放策略 | 改用 `AppNetworkImage`，沿用 28×28 显示、84×84 解码、语义标签和文字后备；接入已有公共 CDN 队列、取消和缓存，不增加另一套图片服务 |
| 主列表与楼中楼自动分页 | 每次向下滚动都先注册帧后回调并请求刷新，到回调执行时才判断距离、加载状态和下一页。远离底部或已经结束的列表仍产生无效调度 | 在注册前先过滤距离大于 240 的滚动通知，以及隐藏、忙碌、加载、失败、无下一页和未加载首屏状态；保留帧后重新读取当前身份、分支和实际布局的检查 |
| 富文本中的时间戳、链接和提及 | 解析时即为所有可识别片段创建 `TapGestureRecognizer`，即使没有对应动作；动态评论中的时间戳是常见例子。移除动作后对象仍保留到正文改变或整行销毁 | 仅在实际存在动作时创建，回调替换复用现有识别器，移除动作立即释放；解析改变和卸载仍统一释放。链接／时间戳颜色及选择、复制行为保持 |

实现入口：[评论列表](../../lib/shared/ui/comments_panel.dart)、[富评论内容](../../lib/shared/ui/comment_rich_content.dart)。`AppNetworkImage` 对支持的公共图片来源复用已有有界传输；其他来源沿用该组件原有策略，不能据此宣称任意外部图片都具有相同缓存和取消能力。

## 已核对而无需改动的生命周期

- 评论数据由 controller 保留，行由 `ListView.builder` 按视口创建；行内内容复用只属于挂载的 `_CommentTileState`，未发现全列表 Widget 缓存或随浏览条数增长的行保活。
- 两组 500 条离线数据分别验证主评论和楼中楼：连续 12 次移动 500 逻辑像素，每次稳定后挂载的富评论组件均少于 30 个；最初的行已卸载，返回顶部重新创建且时间戳仍可点击。这是测试视口下的计数，不是所有屏幕的固定上限。
- 既有分支订阅和内容复用继续隔离分页／点赞的无关重建；回复详情关闭释放数据、主列表位置恢复、草稿和账号代次隔离继续由原实现管理。
- 文本选择、点击识别器和图片请求均由挂载组件拥有，不把这些资源移到 controller，也不通过保留全部评论行来减少重新构建。

## 可复现的结构证据

使用 Flutter 3.47.6／Dart 3.13.5、Windows widget 测试。分页基线仅额外增加 `CommentsPanel.loadMore` 调试标签，便于计数，没有改变调度逻辑。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 主评论，距底部大于 240，20 次向下滚动通知，仍有下一页 | 20 次分页帧后回调 | 0 |
| 主评论，同上，已无下一页 | 20 | 0 |
| 楼中楼，同上，仍有下一页 | 20 | 0 |
| 楼中楼，同上，已无下一页 | 20 | 0 |

行内表情补充两类真实组件测试：

1. 在保留的滚动子树中，两个可见相同表情只产生一条共享传输，屏幕外另一个表情不发起请求；移出视口、隐藏工作区及卸载均取消最后一个未完成消费者，返回可重新加载。
2. 表情解码完成后，移出视口仍保留正文 Element，但图片 stream 的 live 计数由 1 降为 0，`RawImage` 被移除；返回复用缓存帧，总传输次数保持 1。测试在卸载后再次检查 live 计数归零。

不可点击时间戳不再持有点击识别器；测试通过启用、停用、重新启用回调，验证旧对象释放后创建新对象、颜色保留和实际点击结果。

回归位于[富内容测试](../../test/features/video/comment_rich_content_test.dart)、[主评论／楼中楼测试](../../test/features/video/video_comments_controller_test.dart)和[自动分页测试](../../test/shared/ui/comments_auto_pagination_test.dart)。原有短列表补满、接近底部单次加载、失败显式重试、隐藏后恢复、窗口扩大补页以及迟到楼中楼结果隔离均保留。

后续适合实机采样的方向包括密集动画表情的 raster 成本、长正文选择／排版，以及大距离反向滚动的变高行测量和重新解析成本。当前没有测量证明它们是主要瓶颈，因此不增加正文全局缓存、固定行高或全部行保活，也不调整现有滚动手感和列表容量。
