# 固定与滚动弹幕分层对照

日期：2026-11-01。按用户后续要求，参考 PiliPlus 将固定与滚动弹幕分层，并以相同播放面板对比性能。参考基线为 `0e755ab`；本轮不更新播放器或弹幕库依赖。

## 实现与显示语义

只读核对 PiliPlus `936072449e82e3d90c28c728c0087bf5136fa441` 的 [点播弹幕视图](../../../PiliPlus/lib/pages/danmaku/view.dart)，以及其锁定的 `canvas_danmaku 275046d8647a6a26cba1d0dadb9e28688cb3dbf1` 的 `DanmakuScreen`：滚动、固定和特殊弹幕各有 RepaintBoundary，固定层只随内容变化更新，外部仍有 AnimatedOpacity。本项目没有接入高级／特殊弹幕，只采用前两层的职责；未复制 GPLv3 应用代码，也未修改相邻仓库或 Pub 缓存。

[共享分层组件](../../packages/bili_danmaku/lib/src/danmaku_layers.dart)由点播和直播共同使用：

- 滚动层在下、顶部／底部固定弹幕在上。各层内部保持原到达顺序；跨类型重叠现在固定弹幕优先，与之前整层按到达顺序交错不同。这是本轮按用户要求采用的显示变化。
- 保留播放面板已有的整体 Opacity 和用户不透明度设置；没有改成每条或每层分别乘 alpha。因此分层本身不等于取消中间透明合成。
- 两层共用原控制器、唯一 Ticker 和最多一个定时唤醒。每个 Ticker 回调仅做一次入场／过期／位置准备；两位 painter 只消费同一帧，不能分别增加入场预算。
- 可复用的文字位置项只保留该帧可见内容，总量受控制器可见上限约束。固定层依据文字、颜色、字号、位置和样式变化失效；滚动或新条目被轨道拒绝时，不反复录制未改变的固定文字。应用侧没有创建额外位图缓存，两层共用原有文字缓存和 32 MiB 文字像素预算；Flutter 自身的绘制缓存及 GPU 显存占用未单独测量。
- 保留确认媒体时间／直播到达时间、暂停／缓冲冻结、seek、插值上限、倍速、尺寸／DPR 更新、过滤、隐藏及释放规则。纯固定场景仍等待入场／到期唤醒，未限速滚动弹幕或另起动画时钟。

控制器的原 `frame()`／`paintFrame()` 接口继续保留，用于位置快照和直接绘制；界面使用分层准备接口。点播与直播的旧绘制路径回归仍单独执行，不能将它们当作新界面分层的像素验证。

## 验证方法

新增组件与像素回归覆盖：滚动层变化时固定层保留同一 Picture；尺寸与 DPR 变化使固定层更新；移除／清空后清屏停帧；两个 painter 不重复入场；排版缓存仅能容纳一项时，滚动重建／淘汰图像后固定 Picture 的像素仍有效；阴影／描边／纯色与 DPR 1／1.25／2 下，分层结果与“先滚动、后固定、统一组透明度”的逐条对照逐像素相同。点播、直播均覆盖。

性能使用 [生产面板探针](../../tool/validation/playback_gpu_comparison_probe.dart)，同一合成 H.264/AAC、1920×1080、60fps 素材，无真实账号、网络和设置落盘。请求与实际视频输出均为 960×540，字号 25、75% 区域、每秒 20 条、整体不透明度 0.8，音量 0。三种场景为纯滚动、80% 滚动＋20% 固定、纯固定；固定类型在顶部和底部间交替。

每次分别预热并采集纯视频、弹幕、弹幕＋控件，稳定阶段各 10 秒。每场景执行旧→新及新→旧两轮，次轮反向排列场景；采样时串行运行，构建／检查不与性能采样并行。比较原生视频尺寸、解码器、实际可见弹幕数量、绘制计数、Flutter UI/raster、进程 GPU 引擎及整卡时钟／功耗，保留视频掉帧和 A/V 同步诊断。

[对照脚本](../../tool/test-windows-danmaku-layers.ps1)检查两份 bundle 的 Flutter engine 与 libmpv SHA-256 相同，并拒绝输出尺寸、场景、采样长度或播放状态不匹配的结果。原始数据和完整 bundle 位于忽略目录 `build/validation/`；标签为 `layers-20261101a`，12 次运行、36 个稳定阶段全部通过一致性检查。[汇总数据](data/danmaku-layers-performance-2026-11-01.json)保留各次结果、AOT／原生二进制摘要、时钟与功耗。


## 本轮结果

本机 RTX 4070 Ti SUPER，Flutter 3.47.6 / Dart 3.13.5，Impeller OpenGLES，实际硬解均为 `d3d11va`。以下是有控件阶段两轮稳态均值的平均值；图片绘制次数是 Dart 录制计数，不等同于 GPU draw call 数量。

| 场景 | 图片绘制次／秒，前 → 后 | 进程 3D %，前 → 后 | UI 累计 ms／秒，前 → 后 | raster 累计 ms／秒，前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 纯滚动 | 4661 → 4666 | 11.45 → 11.58 | 36.33 → 29.32 | 133.09 → 109.68 |
| 80% 滚动＋20% 固定 | 7242 → 4706 | 13.69 → 9.21 | 34.72 → 33.46 | 132.13 → 131.26 |
| 纯固定 | 344 → 69 | 6.72 → 5.84 | 17.56 → 14.96 | 59.51 → 47.80 |

累计时长用每轮的平均帧耗时乘上报帧数／秒计算，避免固定场景帧数减少后只看单帧平均值产生误判。有控件时，同屏均值依次为 28.40 → 28.30、43.80 → 43.75、17.15 → 17.15；纯滚动与混合均约 165 帧／秒，固定从 82.0 → 62.6。未更改密度或滚动帧率，固定场景减少的是没有显示变化的额外重绘／呈现。固定场景单帧平均 UI 为 214 → 239µs、raster 为 725 → 763µs，单帧并未变轻；累计工作量降低来自帧数减少。

GPU 未锁频、桌面未独占，整卡时钟和功耗也包含其他活动；不能把整卡变化全部归因于本应用。

必须结合以下限制解释结果：

- **纯滚动没有稳定收益。** 它不含可保留的固定文字，图片绘制量不变。首轮 UI 161 → 164µs、raster 629 → 627µs、GPU 12.87% → 12.87%；第二轮原版 UI/raster 偏高，拉低了表中的前后平均值，不能把该平均下降直接归因于分层。
- **混合场景少录制约 35% 图片，但不能确认 GPU 效率提高。** 第一／第二轮原版 GPU 为 14.00%／13.38%，分层为 7.03%／11.38%；整卡核心频率均值却从 232 → 587 MHz，整卡功耗从 17.24 → 23.71 W。raster 累计时长基本不变，因此不能把占用百分比下降宣称成同等幅度的 GPU 优化。
- **纯固定场景有可重复的收益。** 图片录制减少约 80%，UI 累计工作量减少约 15%，raster 累计工作量减少约 20%。GPU 两轮为 6.65% → 5.72%、6.79% → 5.97%；第二轮核心频率均值相同（约 217 MHz）。两轮整卡功耗均值为 17.03 → 15.96 W。收益来自固定层和显示内容修订：轨道拒绝新条目而画面不变时，也不必重绘整组固定文字。

原版混合场景第 1 轮控件阶段末尾的视频掉帧计数增加 3，其余阶段／版本为 0，解码掉帧均为 0；最大上报 A/V 差绝对值约 0.88ms。单轮异常不构成新旧稳定性的统计结论，也不替代人工音画同步验收。

分层按用户要求保留。它明确减少了混合场景中的固定文字录制，并改善固定场景；目前没有证据证明它解决了混合弹幕播放时的整体 GPU 负载差距。组透明合成、视频纹理和高刷最终呈现的成本仍存在。
