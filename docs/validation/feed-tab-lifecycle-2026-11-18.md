# 视频卡列表滚动与标签生命周期

日期：2026-11-18。Flutter 3.50.0 / Dart 3.14.0，Windows x64 本地验证。

## 定位与修复

推荐、热门、视频动态、历史、收藏等页面已使用按视口创建的 Sliver 网格；本轮没有发现恢复成全量创建视频卡的情况。现有自然行高、响应式列数、图片缓存与可见性批处理、滚动时抑制悬停、页面保活和独立滚动位置继续保留。

进一步定位到以下额外工作：

- [共享网格](../../lib/shared/ui/responsive_card_grid.dart)的行高缓存原来在每次 `collectGarbage` 时遍历并重写当前已布局行，即使没有回收任何行。现在只记录即将从开头回收的行；向后跳转仍复用最多 512 行尺寸，缓存不持有组件、图片或播放器。
- [分页视口](../../lib/shared/ui/paged_scroll_viewport.dart)原来每次向下滚动及收到 metrics 通知都安排帧后检查，距离尾部很远、没有下一页、隐藏或已有请求时仍会调度。现在先检查活动状态、分页资格、在途请求与尾部 600px 门槛，再合并检查。初次布局、数据更新、激活与视口变化仍检查是否需要补满页面，回顶按钮继续独立监听位置。
- [视频封面](../../lib/shared/ui/video_card_cover.dart)原来每张已挂载卡片都订阅账号级“稍后再看”变化，隐藏页与不显示操作的卡片也接收事件。现在只在活动、操作可用且悬停／键盘聚焦时订阅，退出交互、隐藏、切换账号操作端口或销毁时撤销。重新显示直接读取当前成员与忙碌状态，不依靠隐藏期间的事件恢复。
- [共享加载状态](../../lib/shared/ui/state_view.dart)原来不消费 `WorkspaceActivity`，在没有外层动画控制的保活页面中，隐藏的加载指示器仍持续安排动画帧。现在只在指示器叶子通过 `TickerMode` 控制可见性；返回恢复同一组件，可见的返回预览仍允许动画。
- [热门页](../../lib/features/feed/presentation/popular_feed.dart)原来在活动状态、分页尾部、错误或目录变化时重新生成视频网格和行委托。现在只在当前不可变视频列表更换时替换网格；缓存只覆盖当前 pane 的一个列表与网格，主题、字体、宽度、账号数据等更新仍按原继承／Provider 路径传递。

作用范围：网格、分页、封面和加载状态是共享路径，因此推荐、热门、分区、搜索、历史、视频动态、收藏／稍后再看及其他使用这些组件的页签共同生效。未增加页面保留容量、延长原生预览生命周期或改变播放会话规则。

## 回归证据

新增用例先在修改前运行，确认分页冗余调度、空闲封面监听、隐藏动画计时和热门网格替换可以复现，再验证修复后行为：

- [分页调度](../../test/shared/ui/paged_scroll_scheduling_test.dart)：距离尾部较远的 20 个滚动帧，分页检查从 20 次降为 0；进入 600px 门槛触发一次检查／请求；无下一页和隐藏时不安排滚动检查，重新激活仍加载。
- [封面监听](../../test/shared/ui/video_card_watch_later_lifecycle_test.dart)：空闲／隐藏／操作禁用时无订阅；真实鼠标进出、键盘聚焦、端口切换和销毁正确释放，显示操作时响应成员变化，返回后读取隐藏期间改变的状态。
- [加载动画](../../test/shared/ui/state_view_activity_test.dart)：隐藏时无动画帧，返回／可见预览恢复，销毁无遗留回调；同时验证隐藏期间 Provider 数据仍更新。既有[保活标签](../../test/shared/ui/retained_tab_activity_test.dart)与[一级页面](../../test/app/workspace_root_page_test.dart)的构建隔离、输入草稿、数据更新和返回状态测试继续保留。
- [热门页](../../test/features/feed/popular_feed_test.dart)：活动与子标签切换保留网格、滚动位置和请求次数；分页加载中、失败与重试复用网格，追加和刷新替换数据。
- [长列表回顶](../../test/shared/ui/sliver_grid_scroll_to_top_test.dart)：窄／宽窗口、数据、字体、缩放、后代尺寸、缓存淘汰与中断场景继续与 Flutter 原始 SliverList 逐帧比较可见行和坐标，确认行高缓存优化未改变布局。

结构计数属于组件测试证据，不能换算为帧率提升比例。原生 Profile 结果及完整检查结果见下文最终记录；本次不将离线假数据回归等同于真实网络、账号或所有平台设备验收。

### 保活与 Riverpod 的边界

复核当前锁定的 `flutter_riverpod 3.4.3` 实现，`ConsumerStatefulElement` 使用 `TickerMode.getNotifier` 暂停／恢复 Provider 订阅。对整个一级页面或子标签新增禁用的 `TickerMode`，会一并改变隐藏期间的数据更新与请求生命周期；既有“隐藏分支仍接收 Provider 更新”回归可以直接检出这一变化。因此本轮保留工作区／标签容器的活动发布方式，只关闭明确的动画叶子，业务 Consumer 继续沿原路径接收账号与数据变化。未修改 Pub 缓存或 Riverpod 依赖。

## Windows Profile 实测

使用普通 `WidgetsFlutterBinding` 运行真实 `FeedScreen`、共享卡片和保活频道，默认 HarmonyOS Sans 主题，每个推荐／热门／视频动态／稍后再看列表各 500 条 fake 数据。封面为内存生成的 640×360 PNG，不访问真实 API、账号或磁盘图片缓存，也不创建原生悬停播放器。每个宽度预热后，推荐与热门分别执行两轮 6000px 下滚／返回，每方向 3 秒，再执行五轮四频道切换。采样覆盖频道内容；一级导航外壳另由完整组件回归验证。

主机 Ryzen 7 7700、约 31 GiB 内存，Windows x64，DPR 1、显示器报告 60 Hz。430／1440 的外窗口对应实际 Flutter 内容宽度 414／1424；已访问的四个列表合计挂载约 48／100 张视频卡，完整领域列表继续保留。采样结束恢复测试窗口原始尺寸和位置。

修复前基线为 `9efab981`。下表为窄窗口有效对照，两轮滚动合并计算 P95；切换为五轮频道往返的合并数据：

| 场景 | 修复前 UI P95 | 修复后 UI P95 | 修复前 raster P95 | 修复后 raster P95 |
| --- | ---: | ---: | ---: | ---: |
| 推荐滚动 | 1.159 ms | 1.163 ms | 0.637 ms | 0.611 ms |
| 热门滚动 | 0.944 ms | 0.934 ms | 0.577 ms | 0.579 ms |
| 四频道切换 | 1.871 ms | 1.797 ms | 0.792 ms | 0.644 ms |

最终宽窗口的推荐／热门／切换 UI P95 分别为 2.421／2.246／2.552ms，raster P95 分别为 0.972／0.960／0.891ms。最终窄／宽窗口共采集 3512 帧，UI 或 raster 超过 16.67ms 的帧为 0。

这些数据未显示稳定的滚动帧耗时改善，不能宣称明显帧率提升。本机场景的原实现已经低于 16.67ms 帧预算；本轮可以确认的收益是上述无效调度、缓存重写、事件订阅、隐藏加载动画与网格替换的减少。不同平台、设备、真实网络与复杂内容仍需单独采样。
