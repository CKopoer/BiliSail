# 评论区组件重建与生命周期优化

日期：2026-10-30。评论相关基线：`264c16a`；分析当前共用评论实现，覆盖视频、影视和动态入口。本轮不变更协议、依赖、写入互斥或 500 条列表容量。

## 组件与更新范围

| 组件 | 状态与原有行为 | 本轮处理 |
| --- | --- | --- |
| 视频包装层／`CommentDetailBuilder` | 视频层注入当前会话的 seek；详情开关只订阅 `openRoot != null`，影响信息区和返回优先级 | 保留现有边界，不把播放 position 引入评论订阅 |
| `CommentsPanel` | 持有草稿、焦点、两个滚动控制器、链接取消令牌；根节点只订阅详情 ID | 保留挂载期间状态；延迟滚动回调核对评论目标与当前详情，避免操作已切换的列表；账号代次变化主动取消链接解析 |
| 标题与排序栏 | 独立订阅排序、总数、忙碌、反馈和详情 ID | 原有拆分有效，保留 |
| 列表 | `ListView.builder`、稳定 ID key、ID 到位置的索引；原订阅同时包含主评论和回复列表 | 只选择当前展示分支的数据／加载／分页字段；保留懒创建、滚动恢复和 500 条上限 |
| 单条评论 | 原 Consumer 将全局 busy/loading 传给整行；分页替换 delegate 时也重建可见行 | 每个已挂载行复用未变化的内容 Widget；数据、展示回调或主题依赖变化时失效。按钮和预览点击层分别订阅禁用状态，重建不传播到头像、作者头、正文和图片 |
| `CommentRichContent` | 已按正文、表情映射、引用用户映射变化重新分段；链接识别器在重新分段和 dispose 时释放；build 更新点击回调 | 保留既有解析缓存与释放。行复用进一步避免无关的 spans、SelectionArea、图片和预览 Widget 重建 |
| 头像／作者头／图片 | 头像、装扮、评论缩略图使用共享图片组件，按视口和工作区可见性管理；正文行内表情仍使用 Flutter Image | 本轮复用未变化行的这些子树，不添加全列表图片或组件缓存 |
| 输入区／表情弹窗 | 草稿在 TextEditingController 内；焦点与表情弹窗控制展开动画，控制状态独立订阅；表情按需加载并随 controller 取消 | 保留草稿、回车、窄屏键盘、发送期间继续编辑和账号隔离行为 |
| `CommentsController` | autoDispose family 按评论身份持有状态；账号变更和 dispose 取消读取、回复、写入、表情请求，以 generation/scope/epoch 丢弃旧结果 | 点赞改为仅复制命中条目和祖先回复分支，未变化列表与条目保持身份；关闭／刷新／排序时释放详情数据并取消详情读取 |

实现位于[共用评论区](../../lib/shared/ui/comments_panel.dart)、[评论控制器](../../lib/features/comments/application/comments_controller.dart)、[富评论内容](../../lib/shared/ui/comment_rich_content.dart)。组件缓存只属于已挂载行；没有为全部 500 条数据建立 Widget 缓存。全局写入互斥仍需让所有已挂载行的操作按钮一起禁用，因此按钮层仍会随 busy 更新。

## 生命周期问题与修正

1. 原点赞递归对每个未命中条目执行 `withReplies`，即使没有回复也创建新的条目和列表。现在仍遍历查找，但只在命中路径复制；主列表、详情根和回复列表中的相同评论都会更新，其余分支复用。既有点赞计数、元数据、不确定结果锁定和单次写入规则不变。
2. 原关闭详情只清除 `openRoot`，最多 500 条 `replyItems` 继续由 controller 保留。现在同时清空回复列表、页码和分页标记；再次打开沿用原有重新读取语义。主评论、主列表位置和编辑草稿仍保留。回复发送期间关闭详情，成功回包只更新主评论中的计数与回复预览，不重新填充已关闭的详情缓存。
3. 原刷新／排序只改变主读取 generation，未取消正在执行的楼中楼读取，也未清理 `replyLoading`。迟到回复虽会丢弃，但 loading 可能继续阻止后续写入。现在先取消详情读取、推进回复 generation，再重置详情状态。
4. 楼中楼本来就要求每次从顶部打开，却使用默认保存 offset 的 ScrollController。现在为详情关闭 `keepScrollOffset`，避免向 PageStorage 逐线程保存无需恢复的偏移。主评论的滚动控制器及回退恢复保持原行为。
5. 切换评论目标、关闭页面、隐藏工作区和账号变化会取消尚未完成的链接解析；详情滚动恢复回调额外核对目标和详情身份。

## 结构计数对照

在 Flutter 3.47.6／Dart 3.13.5 的 Windows widget 测试中，注入 480 条离线评论，每条附一条回复预览，容器宽 340 逻辑像素；再追加 20 条到 500 条。稳定首帧后通过 Flutter 的 `debugOnRebuildDirtyWidget` 统计 `CommentRichContent`，不包含初次挂载。该窗口挂载主评论与预览共 8 个富评论组件。

| 操作阶段 | 基线重建次数 | 优化后重建次数 |
| --- | ---: | ---: |
| 分页请求开始，禁用按钮 | 8 | 0 |
| 分页完成，追加屏幕外 20 条 | 8 | 0 |
| 点赞请求进行中，禁用按钮 | 8 | 0 |
| 点赞成功，更新首条评论 | 8 | 2 |

优化后的 2 次为命中主评论与该行的回复预览，其他可见评论为 0。按钮禁用和恢复均有断言。对照在 `build/validation/comments-performance-2026-10-30/` 的隔离源码副本中进行，两个候选仅替换上述评论区和控制器文件；正式工作区没有为采样回退源码。基线和候选日志为本机忽略文件 `build/comments-baseline-2026-10-30.log`、`build/comments-optimized-2026-10-30.log`。

这些计数证明减少了无关组件构造／重建，不代表真实设备的帧耗时、GPU、功耗或内存改善；没有用 debug 帧率作为性能结论。真实长正文、图片／表情密集评论和 Android/macOS 滚动体验仍需 Profile/Release 实机采样。

## 回归与后续边界

[评论回归测试](../../test/features/video/video_comments_controller_test.dart)新增分支身份复用、已加载详情释放、刷新／排序期间回复取消与迟到响应、分页与 busy 重建隔离、回调／主题／服务端正文更新、详情滚动持久化关闭及组件卸载。现有评论富内容、视频／影视详情返回、双窗口、草稿、账号切换和滚动恢复一并回归。

当前评论及详情上限仍为 500；分页合并和 ID 索引维护仍为有界线性工作。仅剩这些遍历并不足以证明需要引入更复杂的全局索引。输入区动画和布局、密集图片／表情的实际 raster 成本应在设备 Profile 证据后再决定是否优化。

控制器仍订阅完整 AuthState：在当前接口下，同账号 session epoch 的变化可能通过一次 AuthState 通知体现，不能只按 mid／登录布尔值过滤。未来若缩小此订阅，应先提供显式、可响应的 session identity 契约并保持旧响应隔离测试。
