# 列表滚动性能修复

日期：2026-10-07。工具链：Flutter 3.47.6 / Dart 3.13.5。修复前源码基线为 `3b8ed05668e26834106c076f769cc295819379af`，修复后为本轮工作区修改。

## 定位与实现

推荐页原来用 `SliverToBoxAdapter → Column → VideoGrid → Wrap` 一次创建全部已加载卡片。500 条数据时，滚动仍遍历全部卡片的绘制与图片可见性探针；去掉图片后 UI P95 仍为 24.50–24.99 ms，因此主要热点是列表结构。首次离开顶部和分页状态切换还会重建全部卡片，封面三个标签的 `TextPainter` 测量进一步放大突发开销。

修复包括：

- 推荐、热门、分区、排行榜使用 `SliverVideoGrid`；动态使用 `SliverList.builder`，视频动态、番剧、国创、直播、放映厅、收藏、稍后再看等首页子标签使用 `SliverResponsiveCardGrid`。搜索的七种分类和云端观看历史同样改为懒创建列表。
- 网格按行创建，保留自然高度、窄屏两列、宽屏列数和文字缩放规则。滚动约束变化时复用同一行委托，并利用行级绘制边界；数据、卡片动作和横向布局改变时才更新委托。
- 回顶部按钮通过局部 `ValueListenableBuilder` 更新。分页等待、失败和重试只更新尾部，数据未变时复用卡片主体；刷新、换查询、账号状态变化和整页空/错误态清理主体缓存。
- 视频封面标签按实际字体、文字缩放、方向、locale 和文本缓存宽度，每张已创建卡片最多 9 项；字体加载后失效，仍通过真实文本宽度决定布局。

领域列表、分页游标和原有账号/请求隔离保持原策略。UI 虚拟化只减少已创建组件；稍后再看播放队列仍取完整领域列表，历史记录仍按条目索引保留不同分 P 的播放身份。

## Windows profile 对比

使用真实 `FeedScreen`、共享视频卡片和图片提供器，覆盖 20、200、500 条数据。模拟仓储不分页；封面为内存生成的 24×24 PNG，不进行网络、磁盘、真实账号或预览播放。窗口设为 430×900，实际 Flutter 视口为 414×861 逻辑像素，DPR 1。主机为 Ryzen 7 7700、31 GiB 内存；没有核实实际使用的 GPU。

每个样本预热后向下滚动 800 像素再返回，各用 3 秒，重复两轮；由原生引擎 `FrameTiming` 统计 UI 与 raster 时长。另在同一原生进程、窗口和引擎中对比 500 条数据：从上述基线提交只读提取 `FeedScreen`、视频网格/卡片、响应式网格和分页视口，调整临时副本的导入路径后先运行原实现、再运行修复后的生产页面；两者共用未改动的控制器、图片提供器、主题和模拟数据。下表使用这次配对采样的两轮范围。

| 500 条推荐 | 修复前 | 修复后 |
| --- | ---: | ---: |
| UI P95 | 23.84–25.19 ms | 0.31–0.32 ms |
| raster P95 | 12.43–13.47 ms | 4.11–4.26 ms |
| UI 或 raster 超过 16.67 ms 的采样帧 | 419 / 422 | 0 / 778 |
| 初始创建的视频卡片 | 500 | 12 |

前后独立采样中，修复前 20 / 200 / 500 条推荐的 UI P95 分别为 1.28–1.41 / 9.65–9.68 / 25.25–25.54 ms；修复后分别为 0.29–0.36 / 0.26–0.28 / 0.24–0.26 ms，均没有 UI 或 raster 超过 16.67 ms 的采样帧。配对采样再次确认 500 条的全量遍历热点，避免仅依靠不同采样会话推断优化效果。各组结果是本轮合并修复的整体效果，不代表单项文本缓存或按钮隔离独自带来的收益。

本地诊断入口与脱敏 JSON/log 保存在 Git 忽略目录 `artifacts/feed-performance/`：`baseline-profile-results.json` / `fixed-profile-results.json` 为前后独立采样，`windows-paired-results.json` 为同进程对比，`baseline-structural-results.json` / `structural-results.json` 为结构计数。临时探针不进入产品启动流程，也不注册为常规 CI 测试。

结构探针另用组件测试计数，不将 debug 耗时作为性能结论。500 条推荐在相同视口下的变化为：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 初始创建的视频卡片 / 图片组件 | 500 / 500 | 10 / 10 |
| 稳定滚动帧的图片可见性检查 | 500 | 12 |
| 稳定滚动帧的图片探针绘制 | 500 | 0 |
| 首次离开顶部时重建卡片 | 500 | 0 |
| 开始加载更多时重建卡片 | 500 | 0 |
| 追加 20 条时重建卡片 | 520 | 12 |

创建数量随视口和缓存区域变化；上述 10/12 是该探针视口的实测值，不是固定容量。稳定滚动的探针绘制为 0 来自行绘制边界复用，可见性检查仍按原图片策略执行。

## 行为回归与验收边界

新增回归覆盖四个视频频道、13 个其他首页子标签、七类搜索、历史条目；验证数百条数据时创建数量有界、屏幕外组件卸载、分页与刷新、失败重试、列表/收藏夹位置保留和完整稍后再看队列。共享测试覆盖同数量换数据、删除后点击/菜单身份、窗口宽度和文字缩放、布局检查及分页完成时已销毁的视口。

实际 Sliver 中的悬停预览回归覆盖：卡片滚出缓存区后取消请求并单次释放引擎、延迟打开完成不复活，以及隐藏后保留卡片状态但释放预览、重新激活时恢复静止鼠标悬停。文本测量测试覆盖缓存复用、容量上限和字体/显示环境失效。

`tool/check.ps1 -SkipPub` 通过：根应用 1,110、bili_api 291、bili_player 22、bili_danmaku 32 项，共 1,455 项测试；四处格式和静态分析通过，Android 签名边界脚本的 21 项检查通过。结构探针 6 项通过；同进程配对采样与其他 Windows profile 探针正常完成。

诊断完成后通过 `flutter build windows --profile --no-pub -t lib/main.dart` 恢复正常应用入口，输出 `build/windows/x64/runner/Profile/bilisail.exe` 及配套文件。四份改动文档的 100 个本地链接存在，`git diff --check` 通过。

本轮性能证据只覆盖 Windows 原生 profile 的固定模拟数据和窄视口，说明全量组件遍历热点已消除。真实网络图片、长图动态、原生预览播放、低端移动设备、Android/macOS 的帧耗时与实际手感仍需单独实机测量。
